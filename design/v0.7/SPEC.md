# Universal Engine v0.7 — Avatar, Camera & World Presence 設計仕様

- **状態:** Design approved for implementation planning / **未実装**（現行デモの完成版はv0.6）
- **対象:** `universal-engine/` だけ。Kamoku Monitor（現実データの投影）と `frontier-world/`（既存ゲーム）は改変しない。
- **基準:** `planet-explorer/{rig,controller,render,app,geo}.mjs`、`original-assets/original-models.mjs`、`model-lab/`、v0.6の12種GLB
- **成果目標:** 「この人を操作している」「この土地を旅している」と感じられる、人間の動きと世界の見通し
- **設計日:** 2026-10-16

## 0. 既存実装の棚卸し / なぜこの順にするのか

| 項目 | 現行v0.6 | v0.7の変更 |
| --- | --- | --- |
| 人物の骨格 | `rig.mjs`の21ピボット＋剛体セグメント | 既存名を保つ60ピボット定義。LOD/指/顔/鎖骨/背骨 |
| モーション | `samplePose`でその瞬間の歩行/ジャンプ/道具ポーズを生成 | AnimationGraphで待機・歩行・走行・停止・表情を時間補間、上半身の重ね合わせ |
| アバター | `pioneer/scout/artisan` の固定3体を丸ごとGPU交換 | 体格/顔/髪/衣装レイヤー/色の別コンポーネント構成 |
| カメラ | `render.ground()`は近距離三人称、`orbit()`は球体を向く | 追従、自由、肩越し、俯瞰、注視、従来モードを選択。ズームと姿勢を分離 |
| 高度 | 23,000m超でグローブに切替、人物は低高度のみ | 世界座標の人物位置を保持。上空ではマーカー/拡大窓を選択可能 |
| 地形視界 | 地表パッチ半径最大55km、川は簡易分類 | 高低差に応じた遠景LOD、海/谷/山/川の可視性、水平線・霞 |
| 建築 | 屋外小屋を段階描画、地理座標のみ保存 | 将来の屋内/家具/ドア/村向けのID・ローカル空間の契約だけ定義 |

**非目標:** v0.7で完全な高精細スキンメッシュ、リアルな筋骨格、屋内編集、村人社会、動画投影を完成扱いしない。既存GLBを一括再生成する破壊的変更もしない。

## 1. 関節増設・滑らかなアニメーション

### 1.1 60ピボットリグ（v2）

既存21個の名前は**そのまま残す**。`rig-v2.mjs`に拡張階層を新設し、旧関節を名前でマッピング。60ピボットの内訳:

| 部位 | 数 | 内訳 |
| --- | ---: | --- |
| 軸と顔 | 10 | pelvis, waist, lowerSpine, upperSpine, chest, neck, head, jaw, leftEye, rightEye |
| 腕（両側） | 34 | 各17: clavicle, shoulder, upperArmTwist, elbow, forearmTwist, wrist, hand, thumb1/2, index1/2, middle1/2, ring1/2, little1/2 |
| 脚（両側） | 16 | 各8: hip, thighTwist, knee, calfTwist, ankle, heel, ball, toe |
| **合計** | **60** | 新規39、既存21への別名対応 |

関節は位置オフセット`bindTranslationM`、制限角`limitsRad`、親ID、意味タグを持つ。骨長は体型倍率で変更可。頭部の顎と目は演出ピボット。指はLODを下げると握り形状だけに置換。

### 1.2 変形方式

- **v0.7必須:** 形状の分割線が目立たない関節カバー（円筒/球面/交差プリズム）と連続回転、位置・回転の時間補間。見た目の滑らかさをまず改善。
- **次段階:** glTF/GLB `JOINTS_0`＋`WEIGHTS_0`、inverse bind matricesによるGPUスキニング。v0.7では仕様と互換インターフェイスだけ定義。現行の剛体パーツを自動的に滑らかなスキンメッシュと称さない。
- ボーン行列はローカル姿勢から順に計算。頂点が大きく関節に食い込む場合は部品メッシュ側で隙間を調整する。

### 1.3 AnimationGraph

`Animator` は `update(dt, moveSpeed, grounded, action, emotion)` で `AnimationPose` を返す純粋ロジック。

- 状態: idle / startWalk / walk / run / stop / jumpStart / airborne / landing / sword / axe / mine / build / sit（sitは準備）。
- 標準遷移: idle→walk 0.18秒、walk→run 0.22秒、walk→idle 0.25秒、jump→landing 0.16秒。スローモーションは同じ時間スケールで補間。
- 体重移動: 歩行方向・速度・足接地点を使った pelvis移動。足滑り対策は地面接地点を基準に立脚中の足位置を補正。
- 2層ブレンド: 下半身（移動）×上半身（道具/会話/手を振る）。ジャンプ・転倒は全身優先。
- 回転補間: quaternion slerp。大角度でも反転しない最短弧。時間差`dt`を0〜0.05秒でサブステップ、読み込み後初回の飛びを防ぐ。
- モーション速度は歩いた距離から位相を進め、停止中の空回りは防止する。現在の`samplePose`をフォールバックとして維持。
- 右手の道具は手首のアタッチメント行列に追従。左手の両手持ちはIKターゲット（将来の標準接口）。
- LOD: 0〜20mで60ピボット、20〜100mで主要25点、100m以上は低頻度更新/簡略シルエット。数値は初期値として調整可能。

### 1.4 表情・人格との接続

`EmotionState`は `joy, sadness, anger, fear, trust, fatigue, attention`（0〜1）と視線ターゲットIDを保持。ゲーム内の人間関係と表情は**別**に保存し、各状態をそのまま表情へ写さない。顔は目線（左右/上下）、まばたき、眉、口、首の傾き、姿勢、呼吸で表現。

- 笑顔/驚き/悲しみ/警戒/疲れ/平常の6プリセットを補間。
- 表情遷移は0.2〜0.8秒を基準に、急激な表情の飛びや不自然な瞬き連打を防ぐ。
- 会話中だけ相手へのアイコンタクトを強めるなど、`attention`により視線制御。
- 表情・視線には「演出モードOFF」と低負荷モードを設ける。
- **感情移入の設計要件:** NPCには一貫した名前、好み、反応、記憶の表示欄を確保（社会システムはv0.9）。会話での肯定・不安・親愛などの返答時に姿勢/顔を連動。

**受入条件:** 歩行→停止・走行→歩行で腕や脚が瞬間移動しない。60ピボットの親子行列が有限値。既存v0.6 `pioneer/scout/artisan` の歩行・ジャンプ・道具モーションが壊れない。表情の補間0〜1境界で飛ばない。

## 2. アバターと衣装の構成

`AvatarAppearance`は人物の識別（`actorId`）、体型（heightScale/shoulderWidth/armLength）、顔（facePreset/hairStyle/eyeColor）、衣装スロット（`base, inner, outer, legs, feet, head, gloves, cape, belt, bag`）とカラーパレットを持つ。

- 最低10衣装プリセット: 開拓者、斥候、職人、農民、商人、衛兵、司祭、旅人、狩人、村人の日常着。
- 男女・年齢・職業を単一の見た目に固定しない。プレイヤーの衣装自由変更を優先。
- 部位/レイヤーIDはプリセットと独立。服の切替は`avatarStyle`全体のGPU破棄・再作成を避け、差分のあるパーツのみ再構築。
- 衝突を防ぐためマント/髪/袖のクリッピング規則、装備と手のアタッチメント点を用意。
- 色替えはRGBと染色パレット、素材は cloth/leather/metal/wood の見た目係数で表現。高精細PBRは後続。
- 初期プリセットはv0.6と互換。未定義の衣装IDは既定値へ安全に戻す。未所有の装備をセーブから勝手に付与しない（現時点のワードローブは見た目設定のみ）。

**UI:** 設定→人物→プリセット/部位/色/髪/表情プレビュー/戻す。スマホでは半画面シート＋3Dモデル側の大きなプレビュー。

**受入条件:** 服10プリセットが切替可能で、手足/腰の動作中に服が追従する。異なる人物に別々の服装を割り当てても表示が混線しない。保存→再読込で全スロット一致。

## 3. カメラ仕様

### 3.1 モードと視線ターゲット

| `CameraMode` | 用途 | ターゲット | 入力 |
| --- | --- | --- | --- |
| `legacy` | 旧v0.6の地上/球体カメラ維持 | 従来の自動ターゲット | 従来操作 |
| `follow` | 三人称・日常移動（推奨初期値） | `actorId`と肩上0.95m | ドラッグで旋回、移動は独立 |
| `shoulder` | 道具操作・戦闘 | 肩/胸位置 | ピッチ・左右肩切替 |
| `free` | 建築や眺望 | 世界座標 `lat/lon/alt` | 前後左右上下/ドラッグ |
| `orbitTarget` | 人物/建物を360°観察 | 指定したEntity ID | ドラッグ＋距離調整 |
| `tactical` | 高高度俯瞰/村づくり | 人物位置または任意座標 | 拡大縮小/パン/追従ON-OFF |

カメラ姿勢は`CameraState`（mode, targetEntityId, lat/lon, pitchRad, yawRad, rollRad, distanceM, fieldOfViewDeg, followEnabled, shoulderSide, horizonLock, avatarIndicator）として保存。視点移動と人物の地理座標は独立。Freeでカメラを動かしても本人をテレポートさせない。

- カメラ追従は減衰バネ（ダンピング）でフレームレート非依存。`dt`が極端に長いときサブステップ。カメラ切替0.3〜0.7秒で補間、急な視点ワープを避ける。
- 視点衝突: 人物とカメラのレイに地面/建物がある場合は距離を短縮（まず地面のみ、屋内衝突はv0.8）。
- FOV 35〜90°、ピッチ-85〜+85°、距離0.6m〜惑星半径相当、移動速度は高度に応じてスケール調整。
- 高高度`tactical`でアバターは地表の正しい緯度経度に存在し続ける。上空で姿が見えなくなるサイズでは、**明示されたアバターマーカーと任意の拡大窓**で見失わない（何km上空でも等身大で見えると誤解させない）。
- 23km境界で既存`orbit()/ground()`を直接二択にする構成を改め、`CameraController`（視点）→`WorldRenderer`（地形LOD）→`AvatarRenderer`（人物/マーカー）に責務分離。初期版はフェードで切り替え、将来は球面LODへ統合。
- 屋内への移行は`buildingId` + `roomId`で視線ターゲット変更できるイベントフックだけ定義。

### 3.2 UI

設定画面の「カメラ」項目でモード選択、視点距離・FOV・高さ・回転感度・追従強度・高さ制限・アバター位置表示を調整。タッチではスティックを移動用に残し、右側スワイプをカメラに割り当てる。Free中は人物操作との混同を防ぐため明確にFREEバッジ表示。

**受入条件:** 6モードを切り替えても人物座標は変わらない。Legacyに戻せる。100m、1km、10km上空から人物の正しい地点を追跡できる。ロード後も同一モード/距離/FOVに復元。

## 4. 地平線、海・川・谷・山の遠景

`terrainSurface()`と球面緯度経度は唯一の標高データ源として維持。遠景は以下の階層で生成:

| 区間（目安） | 表示 | 技術 |
| --- | --- | --- |
| 0〜300m | 手前の歩行地面・草・川岸 | 地面メッシュ高密度、法線 |
| 300m〜3km | 平地・森林・丘・谷・川 | 中密度チャンク、低LOD樹木 |
| 3〜30km | 山並み・海岸線・湾・大河 | 低密度メッシュ、地形色/霞 |
| 30km〜可視地平線 | 水平線/山影/海面 | 球面曲率を反映した遠景スカート |
| 宇宙視点 | 全球/雲 | 既存の球面を連続LODへ移行 |

理論上の地平線距離は`d = sqrt(2 R h + h²)`（惑星半径R、地表からの高さh、単位m）を基準。空気差・地形による遮蔽は別計算。遠景は実際の地形サンプルに基づき、単なる背景絵にしない。

**水系:** 現在の`Terrain.sample()`の`river`は装飾分類なので、v0.7で見せる川は**簡易河道パスデータ**を導入し、局所メッシュの谷底/河岸/水面と一致させる。長距離の水文学計算・洪水・流路変更はv0.8以降。

**見晴らし検証地点:** 平野から海を望む点、谷と川を見下ろす点、遠くに山脈がある点を**架空惑星の地形から探索して固定**する。海・川・山がどの平地からでも全部見えるとは約束せず、正しい地理的距離と遮蔽を守る。1 km/10 km/100 kmの視野距離で継ぎ目・色飛びなし。

**LODパフォーマンス目標（初期・実機計測で要調整）:** 典型的PC 50〜60FPS、iPhone WebGL2対応機で目標30FPS、メッシュ再生成時のメインスレッド停止50ms未満。動的解像度・描画距離・樹木数・人物骨LODの選択UI。計測環境とフレーム時間p95をレポート。

## 5. v0.8（屋内）・v0.9（村）への契約

今回**インターフェイスのみ**を予約し、操作可能な部屋やAI村人が実装済みだとはしない。

### 5.1 WorldEntity

- `id` UUID相当の安定した文字列（セーブ後も変化しない）
- `worldId`（マルチバース内の世界ID）
- `transform`（外部は `lat,lon,altM` と `yawRad`、内部は `buildingId,roomId,x,y,z` ）
- `components`：`AvatarAppearance`, `EmotionState`, `NavigationAgent`, `Inventory`, `Building`, `Furniture` など（v0.7では定義のみ）
- `ownerId`/アクセス権はマルチプレイヤー時に有効（v0.7ローカルでは単一プレイヤー）

### 5.2 Building / Room / Furniture

`Building{id,worldId,anchorGeo,localYaw,rooms[],ownerId,permissions}`
`Room{id,buildingId,polygon2D,ceilingHeightM,doors[],surfaces[],furnitureIds[]}`
`Furniture{id,roomId,assetId,transform,interactions[],state}`

- ドアは同一世界の室内外境界を持ち、見かけだけでテレポートして地理座標を失わない。
- `SurfaceMaterial`は`baseColor`,`paintLayerIds`,`projectionSlotId`を予約。画像/動画を許可する機能は配信元の権利・音量・プライバシー設定・悪意あるURL遮断を前提にv1以降で検討。
- 家具と壁の編集は、選択/移動/回転/スナップ/取り消しを共通操作にして将来のモデルエディタへ発展させる。

### 5.3 Village / Community

`Community{id,worldId,settlementAnchor,memberIds,householdIds,workplaceIds,resourceLedgerId,roles}`。
人物・家族・職業・所有物・村の資源が互いに参照できるよう、`memberIds`等のStable IDで接続。NPCの仕事や人間関係の処理はv0.9で初めて実装する。

## 6. セーブ・互換・移行

- 現行ローカル保存: `universal-engine:explorer:v1`、フォーマット `ue/explorer-demo`, `version:1`。**既存データは削除しない**。
- 新設の`AppearanceState`,`EmotionState`,`CameraState`は保存時に`v0_7:{schemaVersion:1,...}`の任意フィールドとして追加する暫定方式、または正式版で`version:2`を採用する場合は明示的な`migrateV1ToV2`を必須にする。
- v0.6データを読み込むとき、衣装/カメラ/表情が未登録なら`pioneer`/Legacyカメラ/Neutral表情にデフォルト補完し、建物・歩行位置・惑星経過日数を変えない。
- 不正IDや範囲外値を検査し、異常な`dt`やNaN/Infinityが行列に入らないよう保証。JSONに格納できないGPUリソースは復元時に再生成。
- 設定のプレビュー変更は「適用/戻す」。保存に失敗した場合は既存データを破壊しない。
- 遠景生成はseedと惑星/世界IDで決定論的。同一地点でセーブ→復元後も地形色/川岸/主要地形が一致。

## 7. UIと操作系

- **従来の操作は維持:** スティック、タップ移動、ジャンプ/剣/斧/採掘/建築、全画面、着陸地点切替。
- 設定に「人物」「カメラ」「描画・負荷」「アクセシビリティ」タブを追加。
- 人物タブで上半身の表情プレビュー、衣装10種類＋各スロット色変更。
- カメラタブで6モードと感度/追従距離、任意視点用の速度。
- 操作中はカメラの旋回とキャラ操作を混同しない。タップ移動はFreeカメラでもレイが当たる地面に限る。
- スマホでUIが広すぎるときは、詳細設定を折りたたみ。ボタンの最小タップ領域44CSS px、現在モード表示、短い説明。
- 設定値を変えてもセーブを実行するまでは従来の行動状態に影響しない。モード切替が戦闘中なら安全な補間を使う。

## 8. v0.7受け入れテスト（Definition of Done）

1. 既存21関節名の参照がすべてv2で解決され、60ピボット生成に欠落なし。
2. FK行列と補間値は有限値、回転は最短弧。関節制限を超えない。
3. 60FPS/30FPSのどちらの更新でも、同時間・同入力で同等姿勢。
4. 歩行→停止、走行→ジャンプ、道具→待機で関節の瞬間的な角度飛びを起こさない。
5. 表情プリセット6種・視線・瞬きを試せる。目や顎は顔の剛体パーツで表現。
6. 衣装10プリセット、各衣装レイヤーと体格/髪の選択、複数人物設定の独立性を検証。
7. 6カメラモードの切替で`ExplorerController.lat/lon/x/z`が変化しない。
8. 追従と自由視点、地上0〜12m・100m・1km・10km上空の人物位置追跡と安全なマーカー切替。
9. 遠景の山・海・谷・川・水平線を指定した地形検証地点から表示し、地形の継ぎ目がない。
10. 既存`npm test`成功、v0.6セーブ・v0.7セーブの往復、無効IDの安全フォールバック。
11. iPhone Safari実機タッチと低負荷モード、PCブラウザでの操作・フレーム時間の測定ログ。
12. Kamoku Monitor、Frontier Worldのファイル差分が**0件**、既存v0.6デモが再現可能。
