# Frontier World — 共用クリエイターマーケット β

管理ID: FW-2026-10-12-CREATOR-001 / 導入日: 2026-10-12

## 公開UI

- `frontier-world/creator-market/index.html` : GitHub OAuthによる出品・購入・閲覧・印税確認
- `frontier-world/index.html` : 持ち物→「読書・創作」のマーケット入口
- 制作物は本（本文20〜20,000文字）、楽曲（単音メロディー1〜400音）、イラスト（PNG/JPEGを640pxに縮小）を扱う。
- 原著作を持つ本人が権利申告した作品を「審査待ち」で登録する。公開には別途管理者による確認が必要。権利侵害報告は `fw_creator_reports` に記録される。
- 現時点ではオルガンで作ったMIDIファイルや画像編集アプリのIndexedDB原稿をワンクリック転送する機能はない。作品を新規入力・画像選択して投稿する試作版。
- 青空文庫・古典は無料図書室で読める。著作権満了の原作者に印税は入れない。出典・入力・校正情報は本のデータ側で保存する。

## サーバーと通貨

Supabaseプロジェクト: `kamoku-cloud-v2`。既存の共用マーケットβ（株式市場）と同じ`fw_market_accounts`のオンライン残高を使う。ゲーム内所持Gとは**連動していない**。実通貨・出金・暗号資産とは無関係。

新規テーブル:
- `fw_creator_works`: 制作者の `auth.uid()`、種類、題名、価格、80%印税率、審査状態
- `fw_creator_payloads`: 本文/音符配列/画像。制作者か購入者に限りSELECT可能
- `fw_creator_purchases`: サーバー確定価格・80%印税/20%市場分・依頼IDの決済記録
- `fw_creator_royalty_ledger`: 制作者別の入金台帳
- `fw_creator_treasury`: 運営側取り分
- `fw_creator_reports`: 通報（同一利用者の同一作品の重複を防止）

RPC:
- `fw_creator_submit_work(p_kind,p_title,p_description,p_price_g,p_content,p_original_confirmed)`: サーバー認証UIDに所有権を固定、権利宣誓必須、審査状態`pending`として登録
- `fw_creator_purchase_work(p_work_id,p_request_id)`: `active`のみ購入可、サーバーで価格計算、購入者の利用可能残高を判定。購入者引落・作者80%入金・市場20%入金・購入記録・印税台帳を単一DBトランザクションで処理
- `fw_creator_private.moderate_work(p_work_id,p_status)`: SQL管理者用。ブラウザや一般ユーザーにはEXECUTE権限を付与していない。

## 印税ルール

100Gの作品を購入した場合：購入者 -100G、制作者 +80G、運営 +20G。端数は作家印税の端数切捨て（例：1G販売時は作者0G、運営1G）。単一制作者のみ対応。共同作曲・共著・出版社/レーベルの分配は未実装。

`(buyer_id,work_id)`および`(buyer_id,request_id)`の一意制約を設け、再試行/重複ボタンで二重課金をしない。制作者本人の自己購入は禁止。市場株式口座の拘束残高`cash_reserved`を控除して購入可能額を確認し、口座行は決めた順序で排他ロックする。

## 管理者の作品審査

投稿には直ちに公開権限を与えない。Supabase SQL Editorで権利と内容を確認し、本人の作品だと審査できた場合のみ管理者権限で下記を実行。

```sql
select id,kind,title,creator_id,price_g,created_at
from public.fw_creator_works where status='pending' order by created_at;

-- 実際の作品IDへ置き換える（権利と内容の確認後）
select fw_creator_private.moderate_work('00000000-0000-0000-0000-000000000000'::uuid,'active');

-- 違反・盗用が疑われる作品は非公開
select fw_creator_private.moderate_work('00000000-0000-0000-0000-000000000000'::uuid,'suspended');
```

投稿本文を見る際は管理画面のDB管理権限のみで `fw_creator_payloads` を確認する。作品購入後はダウンロード・転送を完全に防止できる仕組みではないため、DRM対応済みとは表示しない。

## V2: 共同印税・寄贈・NPC・ランキング（2026-10-12）

実装DB migration: `fw_creator_collaborators_donations_npc_rankings_v2` / `fw_creator_avoid_rls_recursion_consent_guard_v2` / `fw_creator_donations_revoke_when_unpublished_v2`。

### 共同制作

- 出品済みの **pending** 作品に限り、著作者から認証済みユーザーのUUIDを指定して最大4人の共同制作者を招待。
- 役割：共同著者／共同作曲者／演奏者／イラストレーター／編集者。
- 被招待者本人のみ、認証ログイン後に「承諾」「辞退」を選べる。招待者は自分のアカウントIDをコピーして共有できる。
- 作者本人の持分は「100%－招待先の割合合計」。作者本人の印税持分は10%以上必要。
- 作品審査時には全員の参加承諾が必須。公開後の割合変更は禁止（一般ユーザーは分配表の直接UPDATE不可）。
- 販売1件につき「販売価格×80%」を分配原資とし、端数は作者に付与。例：価格100Gで作者70%・共同作曲者30%なら作者56G・共同作曲者24G、運営20G。
- 共著の書籍を寄贈する場合は全共同制作者の許諾を取得するワークフローが未実装のため、**共著書籍の寄贈はサーバーで拒否**する。

### 寄贈図書館

- 審査承認済みのオリジナル書籍に限り、所有者本人が寄贈ボタンで無償公開を選択可能。
- 寄贈は不可逆（β仕様）。以降の購入はサーバーで拒否。既存の購入者の閲覧権は維持。
- 寄贈後は市場の「みんなの寄贈図書館」からログイン利用者が無償閲覧可能。
- コモンハウスの書棚にも寄贈図書館へのリンクを追加。
- 作品の非公開・停止後は、未購入者による寄贈本文の閲覧権も遮断する。
- NPC作品、青空文庫を含む権利者不明の第三者著作物は利用者として登録・販売できない。

### NPCによる購入（サーバーの架空需要）

- Postgres pg_cron: `frontier-creator-npc-daily` / `15 10 * * *` GMT = 毎日19:15 JSTに実行。
- 1日最大1件。購入対象は「公開済み・寄贈されていない・過去14日以内にNPC購入されていない」作品のうち1件。
- 運営会計 `fw_creator_treasury` の**当日残高20%を超える印税支出は禁止**。初期残高0Gのため、実際のユーザー売買がない間はNPC購入は成立しない。架空通貨の無からの生成をしない。
- NPC支出額は販売価格×80%。元から運営会計にあるGから共同制作者へ移転する。会計上の20%のマージンはNPC購入によって新たに発生しない。
- NPCの人物名は「司書」「吟遊詩人」「旅の画家」「旅商人」「村人」の例示ラベル。実際にゲーム世界のNPCキャラがアイテムを受領・所持する機能はまだない。
- NPC購入実行権はDB管理者/cronのみ。一般ユーザーのRPCからは実行できない。
- `fw_creator_npc_sales` と `fw_creator_npc_ledger` で購入/印税を追跡。

### 人気ランキングと履歴

- `fw_creator_rankings()`: 作品別に実ユーザー販売数・NPC購入数・販売総額・寄贈フラグを集計。順位は人間購入を重視し、同数なら総売上等で比較。
- `fw_creator_my_income()`: 実購入およびNPC購入からの制作者の受取額を、本人の認証IDで絞って返す。
- 購入者リストや他人の未公開作品本文、他者の私的印税台帳は外部へ返さない。

### セキュリティ/動作検査（V2）

- 共同制作の追加・承諾・寄贈の未ログインRPCは `login required` として拒否。
- 一般ログイン利用者に管理者審査権・NPC決済実行権・共同制作者割合UPDATE権なし。
- 寄贈非公開時のRLSを修正。全表RLS適用済み。
- cron設定（GMT）と1日1回実行設定を確認、作品0件の状態のNPC決済は `no_public_works` を返した。
- UI JavaScript構文を検査。GitHubリポジトリにコードと仕様をコミットした。
- **未完了**：実ユーザー2名での招待と承諾、実売買と分配金入金、招待→審査→購入→寄贈のブラウザ通しテスト、NPCの予算あり時の1日1回試験。

## V3 — 音楽を端末へ保存・追跡するライセンス発行（2026-10-12）

対象画面: `creator-market/music-download.html`  
出力エンジン: `creator-market/music-export.js`

**できること**

- 共用マーケットで購入済みのオリジナル楽曲、本人が出品した楽曲、参加承諾済みの共同制作楽曲を、端末へWAV（レコード音声）、MIDI（演奏用データ）、MusicXML（編集可能な楽譜）として出力する。
- WAVは曲の音符列から合成した簡易音声であり、演奏者の生録音・オルガンの録音ではない。現在の楽曲入稿形式は音符・音程配列、最大400音。
- 保存されるファイルの本体内部に `FW-DL:<UUID>;WORK:<UUID>` を埋め込む。MIDIメタテキスト、WAVのLIST/INFO/ICMT、MusicXMLの`identification/rights` に対応。
- ライセンスを発行したサーバーに、発行日時、ファイル形式、発行先アカウントUUID、元の購入ID（購入者の場合）を記録。購入者の個人情報は第三者向け照合では返さない。
- ブラウザはまず登録済み権利を照合するRPCを呼び、発行IDを取得する。ライセンス付きメディアを合成してSHA-256・ファイルサイズを計算し、発行IDへ変更できない形で記録。**サーバー登録が成功してから**保存リンクが有効になる。
- 再ダウンロードするたび新しい発行IDを作り、すべての発行を追跡可能にする。元の購入権は再利用し、追加精算0G。
- 検証画面では、端末に保存したファイルから発行IDを読み取り、公開RPCで「存在する発行記録」とファイルSHA-256・サイズ一致を検査。発行ID照合だけならファイルの所持は不要。
- 権利者向け匿名集計として作品・形式ごとのライセンス発行数とファイル生成件数を表示。所有者本人には発行履歴を表示。
- 出品作品は初期`pending`で管理者の著作権・利用規約審査が必要。第三者の楽曲、既存商業曲の無断複製は禁止。

**コイン配分**

- 印税精算は従来の`fw_creator_purchase_work`一度だけ。例：100Gを初購入→購入者-100G／権利者へ80G（共同制作者がいればその比率で配分）／市場会計へ20G。
- この初回購入IDを新しい`fw_creator_music_downloads.purchase_id`へ関連付ける。ファイル保存によって再課金、再発行、新たな印税支払は**発生しない**。
- 出品者・共同制作者による自作品の書き出しは無料、他人の有料作品は決済/権利が存在しない限り発行拒否。

**新テーブル / RPC**

- `public.fw_creator_music_downloads`: `receipt_id`（主キー`id`）、`work_id`、`user_id`、`purchase_id`、`license_type`、`format`、`issued_at`、`sha256_hex`、`file_size_bytes`、`prepared_at`。
- `fw_creator_issue_music_download`: 認証必須、作品権利/購入権のサーバー確認、1回の発行を記録（この操作だけではコイン移動なし）。
- `fw_creator_prepare_music_download`: 本人発行済みIDにSHA-256とサイズを**初回だけ**紐付け。別データに再登録不可。
- `fw_creator_verify_music_download`: 誰でも発行IDとファイル指紋を照会可能。購入者のUUIDや課金情報は返さない。
- `fw_creator_my_music_downloads`: 本人の発行履歴。
- `fw_creator_music_download_summary`: 本人が権利者（原作者または参加済み共同制作者）の楽曲の形式別集計。

**検査**

- Supabaseマイグレーション `fw_creator_music_licensed_download_receipts_v3` 、公開照合スキーマ使用許可 `fw_creator_music_public_receipt_validation_v3` 適用済み。
- RLSを設定し、一般認証ユーザーの直INSERT/UPDATE、未認証ユーザーの発行を拒否。公開照合のみ匿名アクセス許可。
- SHA-256照合のRPCを匿名DBロールで実行できることを確認。未認証の発行RPCは拒否。
- WAVのRIFFサイズ、MIDIのトラックチャンク長、3形式の受領ID埋込/抽出をサンプルで検査。
- **未実施**：2アカウントを使った本番決済→DL→印税照合、実際の端末へのファイル保存完了検知、iOS Safariでの保存操作、外部MIDI/楽譜アプリでの互換性確認。

**重要な限界**

ファイルのSHA-256はクライアントが発行時に申告したバイト列の照合であり、サーバー署名付き音声の真正証明ではない。著作権保有の法的証明、転送防止DRM、不正コピー追跡や削除にはならない。サーバーは端末で保存完了したかどうかの情報を取得できず、発行済みとファイル準備完了のみを記録する。秘密鍵による電子署名・サーバー側メディア生成・正規版ウォーターマークは後続課題。



## V4 — 村のBGMから購入・販売者/音源製作者/作曲者への分配（2026-10-12）

管理ID: `FW-2026-10-12-CREATOR-004`

### ユーザー導線

- ゲームの「🎶 BGM」から共用マーケットの**購入済み・自作・共同制作**の音符楽曲を選び、実際のゲームBGMとして演奏可能。ログイン済みの権利者/購入者のみ全文データ取得可能。
- BGMメニューの「💿 曲を保存」から`creator-market/music-download.html?work=ID`へ移動し、ライセンス付きWAV/MIDI/MusicXMLを保存。
- BGMメニューの「🌍 村のBGMに公開」で村名と曲IDをオンライン登録し、専用の村の共有URLを提示。
- `creator-market/village-bgm.html` にオンラインの音楽村リストを表示。村を選ぶとその村の曲名/価格を表示し、冒頭8音をWeb Audioで試聴できる。試聴では購入や印税精算は発生しない。
- 村の音楽を気に入った訪問者が「購入して保存する」を押すと**初回だけ**オンラインβ Gをサーバー側で原子的に決済。購入済みならボタンは再課金せず、ライセンス付き楽曲ダウンロード画面へ移動可能。
- 現状の「訪問」は村の音楽ポータル訪問。3D/2Dワールド内で別のユーザーの実際の村へアバターを移動させるマルチプレイ同期は未実装。

### 正確な分配方式

初回の**村経由購入**のみ、100Gの支払いの内訳は販売者（村の曲紹介者）10G、楽曲権利者全体70G、マーケット会計20G。
楽曲権利者70Gは作品の原著作者と承諾済み共同制作者の出品時に定めた配分率で配る。「共同作曲者`composer`」「音源製作者`producer`」が独立した受取人になり得る。原著作者は残余を受け取る。端数は原著作者へ付与。
販売者本人が権利者でも、販売者10Gと権利者取り分の双方を受け取る。販売者は当該作品を購入または作成済みであることが必要。
100G / 共同音源製作者50% / 原著作者50%の場合：購入者 -100G、紹介販売者 +10G、原著作者 +35G、音源製作者 +35G、市場会計 +20G。
村以外の**共用マーケット直接購入**は従来どおり制作者80%・市場20%であり、紹介販売手数料は発生しない。
**再ダウンロードでは追加のGを一切引かず、印税・紹介料ともに重複計上しない**。端末保存時のライセンス発行履歴は前節のV3機構へ記録される。

### 著作権・公正性

- 曲の作成時、制作した音符列の冒頭8音を村で宣伝用に公開することについて、権利者が明示的にチェックを付ける。無許可の曲は`fw_creator_set_village_bgm`が拒否。
- BGMに設定できるのは審査承認済みのオリジナル作品かつ所有/購入/共同制作権のある曲だけ。青空文庫・第三者作品の勝手な販売はできない。
- 公開プレビューRPCは完全な楽譜を返さず8音を上限とする。iOSでは▶再生の明示操作が必要。
- `buy_village_bgm`決済RPCには確認済みの曲ID・価格を同時送信。販売者が確認から決済までに村BGMや価格を切り替えた場合、予期しない購入/金額ではなくエラーとする。
- 本人の自己売買や自身の村での買い戻しを禁止。購入時の既存の拘束残高を尊重し、ウォレット更新、購入履歴、印税台帳、村販売者報酬、市場会計を1トランザクションで記録。
- 作品と決済の照合元はサーバーの`auth.uid()`、書き換え可能なユーザーメタデータを権限判定には使わない。
- 村の販売者取り分は`fw_creator_village_music_sales`に記録し、本人の`fw_creator_my_income()`にも`village_seller`種別で表示。
