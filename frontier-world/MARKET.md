# Frontier World — Online Share Market Architecture

更新日: 2026-10-05 JST  
管理ID: `FW-2026-10-05-004`

## 目的

Frontier World 内の会社株式を、将来的に複数ユーザーが共通マーケットで売買できるようにする。

V36で投資指標・配当予想を実装し、V38で市場口座・保有株・注文・約定をサーバー正本化したオンライン市場βを実装した。

## なぜローカルセーブをそのまま使わないか

GitHub Pages上のゲーム状態はユーザーのブラウザで動作するため、ローカルのGや株数だけを信用してオンライン市場へ接続すると値を書き換えて不正な資金・株式を作れる。

そのためオンライン市場では以下をサーバー側の正本とする。

- 市場口座残高
- 利用可能残高 / 注文拘束額
- 会社ごとの保有株
- 利用可能株 / 売却注文拘束株
- 注文
- 約定
- 配当支払履歴

## 想定バックエンド

既存 Supabase `kamoku-cloud-v2` を利用候補とする。

- Auth: ユーザー識別
- PostgreSQL: 市場台帳、注文、保有株、約定
- Realtime: 注文板・歩み値更新
- RLS: 自分の口座/保有株へのアクセス制御

フロントエンドには publishable key のみを配置し、service role/secretは置かない。

## 注文板

基本優先順位:

1. 買い: 高い価格を優先
2. 売り: 安い価格を優先
3. 同価格: 早い注文を優先

将来対応:
- 指値
- 成行
- 部分約定
- 注文取消
- 板情報
- 歩み値
- 出来高
- 高値/安値/始値/終値
- 値幅制限の有無を会社/市場ルールで設定

## 決済

注文受付時:
- 買い注文は必要Gを拘束
- 売り注文は必要株数を拘束

約定時は1トランザクション内で:
- 買い手拘束Gを減額
- 売り手市場口座へ売却代金を加算
- 売り手拘束株を減額
- 買い手保有株を加算
- 双方の注文残数量を減算
- 約定履歴を追加

どこか1つでも失敗した場合は全処理をロールバックする。

## セキュリティ

- クライアントから口座残高・株数を直接UPDATEさせない。
- 注文作成時に認証ユーザーをサーバー側で確認。
- 自己売買を拒否。
- 残高/保有株不足を拒否。
- 同じ注文を二重約定しないよう行ロックを使う。
- RLSを全公開テーブルに設定。
- セキュリティ上重要な決済関数は実行権限を限定する。
- オンライン市場のGをローカルGへ接続する前に、ゲーム側通貨もサーバー正本化するか、検証可能な入出金方式を用意する。

## オンライン化の段階

Phase 1: V36 — 完了
- ローカル投資指標・配当予想。
- オンライン市場の安全設計。

Phase 2: V38 — 完了
- Supabase Authをゲーム本体へ接続。
- 市場口座/保有株/注文/約定テーブル。
- GitHub OAuth UI。
- 板・歩み値。
- Realtimeティッカー。

Phase 3: V38 — β実装完了
- サーバー原子的決済。
- 指値注文。
- 価格優先・時間優先。
- 部分約定。
- 注文取消。
- G/株の拘束。
- 自己売買除外。
- 公開テーブル直接更新禁止。
- 決済処理を非公開スキーマへ隔離。

Phase 4 — 未実装
- ゲーム内Gと市場口座の安全な入出金。
- ユーザー所有会社の上場。
- 新株発行、希薄化、TOB。
- オンライン会社決算・配当決済。
- PBR/PER等を共有市場価格と共有財務へ統合。

## V38 β仕様

- 初回市場口座: 1000 βG
- 上場会社: Frontier Trading Company
- 発行株式: 100株
- 初期IPO在庫: 100株
- IPO価格: 10 βG/株
- 注文上限: 1注文につき発行済株式数以下
- 未約定注文上限: 1ユーザー/会社あたり50件
- 市場用βGはゲーム内Gと別勘定
- OAuth redirect: `https://hublab055-crypto.github.io/kamoku-world-monitor/frontier-world/`

## DBセキュリティ

- 公開テーブルは全てRLS有効。
- authenticatedはSELECTのみ。直接INSERT/UPDATE/DELETE不可。
- anonは市場RPC不可。
- 決済コア: `fw_market_private`（Data API非公開）。
- 公開RPC: SECURITY INVOKER。
- 非公開決済関数: SECURITY DEFINER + `auth.uid()`確認 + 固定search_path。
- Realtimeには個人情報を含まない `fw_market_ticker` のみ公開。
