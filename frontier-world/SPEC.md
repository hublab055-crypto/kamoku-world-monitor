## 1. ゲームの方向性

Frontier World は、2D の開拓生活シミュレーションを中心に、RPG、家族・世代交代、クラフト、戦闘、農業、住民AI、自動行動（ガンビット）を統合するゲーム。

中心ループは次の通り。

- 資源を集める
- 野営地を発展させる
- NPC と関係を築く
- 仲間へ仕事を任せる
- 家・家具・生活設備を作る
- 料理・道具・衣服・装備・アクセサリーを制作する
- 畑、狩り、釣り、戦闘、訓練を行う
- 結婚・出産・育児・成長・継承を通じて世代をつなぐ
- プレイヤー/NPCの予定表と自動行動で生活を自律化する

## 2. 現在の主要キャラクター

- Mio: 採集・料理寄り。表情、瞬き、口パクあり。
- Riku: 採集・制作・建築寄り。
- Guard: 警備、巡回、剣・弓訓練。
- Shop / Merchant: 売買、農業用品、レシピ本。
- Player: 操作キャラ。家族・忠誠の高い人物へ操作権を移せる。
- Children: 赤ちゃん → 少年/少女 → 成人。成人後は結婚・家族拡張の対象。

### 雇用・日給・忠誠（V32）

実装済み。

- Merchant を除く会話対象NPCを、会話の「💼 雇う」から日給制で雇用できる。
- 雇用開始時に初日の日給を前払いし、その日から既存の採集・料理・制作・建築などの仕事指示を利用できる。
- 日付が変わるたびに給料を自動支給する。
- 日給は固定値ではなく、本人の「職能Lv」と現在のスキル値で再計算する。
- 現行式: `max(4, round(4 + 職能Lv×1.5 + 上位2スキル合計×1.25 + 役割補正)) G/日`
- 役割補正の初期値: Guard +2G、Gatherer +1G、Family +1G。
- 給料が当日分まで支払われている間、忠誠心は最低75を保証する。友好・家族・プレゼント等で75を超えることはできる。
- 給料を払えない日は、その日の日給を未払い賃金として記録し、忠誠心が12低下、仕事は停止する。
- 未払い中は追加の日給を積み上げず、未払い分を精算するとその日から仕事へ復帰する。
- 契約終了後も未払い賃金が残っていれば精算可能。
- 給料を支払った日数で職能XPを獲得し、`職能Lv×10 XP` ごとに職能Lvが上がる。レベル上昇は次回以降の日給へ反映される。
- 雇用情報は `npc.employment`、給与履歴・最終給与処理日は `state.employment32` に保存する。
- 旧セーブには雇用データを自動補完し、過去日に遡って給与を請求しない。
- 給与原資は既存の `state.player.coins` を使用し、雇用UIでは G と表示する。

- 「商人を雇う」と「会社を所有する」を別契約として扱う。
- 商人だけを専属契約して、既存会社の交易手数料を得ることができる。
- 商人の日給は通常雇用とは別に商人向け最低8G/日とし、職能Lv・交易を含むスキルから再計算する。
- 商人が専属契約中でも店頭に残り、通常の商売NPCとして行動する。
- 商人の会社 `Frontier Trading Company` を資金が十分なら買収できる。
- 会社買収後は店舗・会社資金・信用・利益履歴を引き継ぐ。
- 会社所有と商人雇用は独立しているため、以下を選べる。
  - 商人だけ雇う
  - 会社だけ買う
  - 会社を買い、商人を店長/管理者として雇う
- 自社を商人なしでも経営できるが、営業効率は低下する。
- 商人を雇っていると交易Lvに応じて売上効率が上がる。
- 会社は日ごとに売上・運営費・純利益を計算し、会社資金へ反映する。
- 商人所有会社で商人を専属契約している場合、売上の一部を交易手数料としてプレイヤーへ支払う。
- プレイヤー所有会社では商人の日給を会社資金から支払う。独立会社の商人契約はプレイヤー個人資金から支払う。
- 通常の店頭売買、農業用品、レシピ本、制作物売却を会社資金の入出金へ連動する。
- 会社所有後は個人資金から会社への出資、会社資金からの引き出しが可能。
- 会社は後から売却可能。売却価格は企業価値の約85%。
- 企業価値は会社資金、直近利益、信用を基礎に動的計算する。
- 商人・会社データはセーブ対象で、旧セーブでは `state.commerce33` を自動補完し過去日の商業損益は遡及計算しない。


### 株式・配当・段階的買収（V35）

実装済み。

- `Frontier Trading Company` を100株に分割し、1株=1%として扱う。
- プレイヤーは1株、5株、10株単位で段階的に株式を購入できる。
- 株価は現在の企業価値を100株で割った値を基準に毎回再計算する。
- 通常の株式購入は既存株主からの取得として扱い、購入代金は会社資金には入らない。
- 株式売却は基準株価の95%で売却する簡易市場モデル。
- 残り全株を一括取得する「公開買付」は基準価格に10%の買収プレミアムを上乗せする。
- 1%以上: 株主。持株比率に応じて配当を受け取る。
- 10%以上: 大株主。
- 34%以上: 重要株主。
- 51%以上: 経営権を取得。会社の支配主体をプレイヤー側へ切り替える。
- 100%: 完全買収・100%子会社。会社資金の直接移動も可能。
- 51%以上では配当性向を0% / 30% / 60% / 90%から変更できる。
- 配当は黒字日の純利益 × 配当性向を基礎とし、会社資金を上限に配当総額を決定する。
- プレイヤーの受取配当 = 配当総額 × 持株比率。
- 配当総額は会社資金から控除する。他株主分の配当先資産は現段階では個別追跡しない。
- 51%以上では会社への増資を指示できる。
- 51〜99%では会社資金を個人資金へ直接引き出せない。利益回収は原則配当を使う。
- 100%保有時のみ会社資金を個人資金へ直接移動可能。
- 持株比率が51%を下回れば経営権を失い、会社支配は商人側へ戻る。
- V33の「会社を丸ごと買収」はV35では「残り全株の公開買付」へ置き換える。
- V33ですでに会社を完全買収済みの旧セーブは、V35移行時に100株保有へ自動変換する。
- 未買収の旧セーブは0株保有から開始する。


### 投資指標・配当予想・ユーザー市場設計（V36）

投資指標と配当予想は実装済み。ユーザー間オンライン市場は安全なサーバー正本化を前提に設計済み・接続前。

#### 投資指標
- 株式・会社画面に以下を追加。
  - 株価
  - 時価総額
  - 簡易純資産
  - BPS
  - PBR
  - 30ゲーム日予想利益
  - 予想EPS
  - 予想PER
  - 現在の配当性向
  - 予想配当総額
  - 1株予想配当
  - 予想配当利回り
  - プレイヤー保有株数に応じた30日予想配当
- 予想利益は直近7日平均利益を30ゲーム日へ延長して算出。
- PER/EPSは「30ゲーム日を1期」とした予想値として扱う。現実の暦年PERとは別物。
- 簡易純資産 = 会社資金 + 店舗等固定資産 - 負債。
- 初期固定資産は120G、負債は0G。将来の設備購入・借入システムと連動予定。
- PBR = 時価総額 / 簡易純資産。
- 予想PER = 時価総額 / 30日予想利益。予想利益が0以下の場合は表示不可。
- 予想配当総額 = max(0, 30日予想利益) × 現在の配当性向。
- 1株予想配当 = 予想配当総額 / 発行済株式数。
- 予想配当利回り = 1株予想配当 / 現在株価。
- プレイヤー予想配当 = 1株予想配当 × 保有株数。
- 配当性向を0/30/60/90%へ変更すると、予想配当値も即時再計算される。

#### ユーザー間マーケット
- 最終形はユーザー同士の指値注文を注文板で突き合わせる。
- 優先順位は「価格優先 → 同価格なら時間優先」。
- 成行注文・指値注文、取消、部分約定を将来対応する。
- 注文、約定、市場口座G、保有株、拘束中G、拘束中株はサーバー側を正本とする。
- ブラウザのローカルセーブ値だけをオンライン市場へ入金・入庫することは禁止する。クライアント改ざんで無限G/無限株を作れるため。
- 市場用バックエンド候補は既存Supabase。Authでユーザー識別、Postgresで台帳・注文・約定、Realtimeで注文板更新を配信する。
- RLSを有効化し、ユーザーは自分の市場口座・保有株だけを直接参照可能にする。
- 残高・保有株・約定更新はクライアントから直接UPDATEさせず、認証済みサーバー処理で原子的に決済する。
- 自己売買、残高不足、保有株不足、二重約定、同時注文競合をサーバーで拒否する。
- 現在のV35株式売買はオンライン接続前のローカル簡易市場として残す。

## 21. 現在の既知リスク

- `frontier-world/index.html` は自己完結型で非常に大きい。機能追加が続くほど競合・回帰バグのリスクが高い。
- ゲームコード、セリフ、データ定義を段階的に外部ファイルへ分割した方がよい。
- A* は簡易実装で、密集した建物や動的障害物ではまだ立ち往生の可能性がある。
- 大人数のNPC・家族・衛兵を増やす場合、描画・経路探索・AI判定を時間分散する必要がある。
- セーブデータはブラウザ localStorage。端末/ブラウザを跨いだクラウドセーブは未実装。
- 雇用UIは通貨を G 表記する一方、既存ショップには C 表記が残る。通貨表記の統一は未実施。
- 株式市場は現在、他の投資家や注文板を持たない簡易価格モデル。売買流動性、需給、株価変動は今後拡張。
- 非プレイヤー株主へ支払われた配当は会社資金から控除するが、個々のNPC資産としては未追跡。

## V40 — 2026-10-07 — コンテンツカタログ基盤（建物・アイテム・道具・家具）

### Creator Suite
- アイテム / 道具 / 建物 / 家具を独立タブ化。
- 標準カタログの手動読込ボタンを追加。
- 起動時にも不足IDを自動マージ。
- 既存ローカルデータは同一IDなら優先し、カタログ側の未定義フィールドだけ補完する。

- レシピ完成品は item / tool / furniture のいずれも参照可能。
- 修理素材、建築素材、家具制作素材の参照切れを検証する。
