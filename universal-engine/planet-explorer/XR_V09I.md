# Universal Engine v0.9i / WebXR VR・MR

## 目的と互換性

既存の Planet Explorer の独自 WebGL2 メッシュ・物理シミュレーション・保存形式は維持したまま、WebXR のステレオ描画と透過 MR 表示を追加する。VR / MR は描画モードであり、セーブ形式・主人公の立ち位置・支配権・土地データを変更しない。

## 起動

Planet Explorer 上部の「🥽 XR」から切替。

- **VR・立体視** — immersive-vr。地上では等身大・頭追従の視点。惑星高度では宇宙に球体模型を表示。左スティックで移動、右スティックで回頭。
- **MR・卓上RTS** — immersive-ar。地表の既存 WebGL メッシュ、建造物、人物を 1:714 のホログラム模型として表示。モデル縮尺は 1:1429 / 1:714 / 1:357。色付きの輪は操作できる人物を示す。コントローラのトリガーで近くの味方を選択、グリップ（squeeze）で選択者へ移動指示。
- **MR・惑星模型** — immersive-ar。実空間の前に直径48cmの球体模型を表示。現行惑星の地形・大気・雲を使用。
- **XR終了** — WebXRセッションを終了し、従来の2D画面描画に戻る。ヘッドセット本体の退出操作でも可。

初期アンカーはヘッドセット正面。ARヒットテスト対応機器ではトリガーにより検出面へ再配置。ヒットテスト非対応機器では正面へ再配置。ハンドトラッキング、実空間の遮蔽、永続アンカー、自動縮尺校正は今後の開発課題。

## 技術設計

- `xr-spatial.mjs`: 列主順の4x4行列、VR原点、MR模型のステージ変換、RTSポインタの逆変換。Nodeのユニットテストあり。
- `xr-ui.mjs`: `navigator.xr` の能力確認、ユーザー操作からの `requestSession`、`XRWebGLLayer`、`requestReferenceSpace`、ヘッドセット描画ループ、XR入力、セッション終了時復帰。
- `render.mjs`: 通常の WebGL 描画を保持。XR有効時だけビューごとの projection/view を使用し、XRのフレームバッファと viewport/scissor を使う。MRでは背景アルファ0、VRでの主人公頭部の描画を抑制。
- `app.mjs`: シミュレーションループは変更せず、XRセッション中の通常画面用レンダーパスだけを止める。主人公、仲間、惑星データを共有する。

## 動作条件・注意

- HTTPS または localhost の secure context、WebGL2、WebXR、immersive-vr / immersive-ar に対応する機器とブラウザが必要。
- 対応していないボタンは無効化され、通常の TPV / RTS / 惑星表示は従来通り利用可能。iOS Safari は WebXR immersive mode を公式にサポートしていないため、iPhone単体で真のパススルーMRは使えない。
- MR・VRの実機描画性能とコントローラー軸構成は機種によって異なる。高密度の町、NPC集団、広域RTSは負荷が高い可能性あり。画面での自動テストは数学・静的検査が中心で、機器テストは別途必要。
- 立体視ではヘッドセットの周囲を片付け、着座または安全を確保した範囲で使用すること。現実空間の障害物衝突判定は実装していない。

## 受け入れ基準

1. XR非対応端末では説明文と無効化したボタンが表示され、通常ゲームが起動する。
2. VR対応端末で地表の左右眼描画・位置と頭の追従ができる。
3. AR対応端末でRTSと惑星が透明背景のステレオ模型になる。
4. MRでのトリガー選択・グリップ移動指示が元の `SquadEngine` を利用する。
5. WebXRセッション終了後に通常描画へ復帰し、セーブデータ構造に変更がない。
