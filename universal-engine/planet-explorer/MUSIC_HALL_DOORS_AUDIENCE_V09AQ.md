# Universal Engine v0.9aq — 音楽施設の扉・徒歩入退場・衝突・観客動線・チケット着席

## 位置付け
先行PR #66（劇場・教室の室内とQuest指先演奏）に対して、既存の街の地表→音楽施設の入口→歩ける室内→出口へ戻る行動を追加する。
過去の住人ID、建物ID、鉄道・惑星・再基準化・地形描画のコアコードは変更せず、既存の`ExplorerController`と`TownLife`を利用する。依存は #60 → #61 → #62 → #64 → #65 → #66 → 本PR。

## 変更
### 1. 扉の開閉と地表からの入場
- `music-hall-portal.mjs`に劇場/学校の正面扉位置、簡易AABB壁衝突、扉の横断判定を記述。地表からの移動は`controller.x/z`のローカルメートルを利用し、惑星原点の再基準化処理には介入しない。
- 劇場・音楽教室の外観は、以前の「暗色の扉風の壁」を穴の開いたファサードに変更。独立した扉の葉をWebGLで描画し、閉じているときは入口を塞ぎ、開いているときは蝶番を軸に回転する。
- 扉を開閉するには正面から約2.5m以内。室内からは出口の約2.5m以内かつ非着席で操作。
- 扉を開けた状態で入口を横断した時のみ、`TownLife.enter`を自動実行。扉が閉じている、または別の壁に進もうとした場合は移動直前の地表座標に戻し、`controller.blocked`へ反映。
- 従来の「建物に入る」ボタンは残しつつ、扉が閉じている場合は先に開ける必要があるよう変更。
- 開閉ボタンは「🎭 音楽文化」と「🏘️ 街の生活」の両方に追加。扉の状態はTownLifeの一時セッション状態で、セーブ形式を変更しない。

### 2. 室内からの徒歩退出
- `TownLife.walk()`で座標の北側、室内出口に近づくと、扉が開いている場合だけ`portalExitRequested`を立てる。
- `TownLife.portalExit(actor)`は出口の屋外局所座標と`ExplorerController.locationAt`から正しい緯度/経度を計算し、歩行制御を屋外に戻す。
- 室内は今の実装どおり専用描画パス`renderTownInterior()`を使用するため、屋外→屋内の描画切替は発生する。大規模な共通レンダラーによる完全連続描画には未達。ただしユーザーはボタンなしで扉を歩いて通過して入退室できる。

### 3. 客席・舞台の衝突と有料席
- 劇場/学校の室内では壁を越えないよう余白を持たせ、座席と舞台の簡易矩形衝突を追加。中央通路は歩行可能。
- 以前の着席/起立は維持。着席中は移動不可、立ち上がると再開。
- **劇場公演中**は`MusicCulture.hasTicket()`が当該公演のチケット購入または出演履歴を確認し、未購入なら客席へ着席できない。
- 前段の`MusicCulture.attend()`が実際に所持金と会場資金を処理し、重複購入を防止する。学校の椅子や公演時間外の劇場席はチケット制限を適用しない。
- この段階では劇場自体への入場や通路で立ったままの鑑賞は無料。チケットは**指定席ではなく公演の着席権**であり、席の予約・払戻し・退場後の再入場処理は次段階。

### 4. 観客の入退場
- `hallAudiencePose(kind,index,planetDays,shows)` は観客ごとに決定論的な座標を返す（人物インスタンスの常時AIシミュレーションは不要）。
- 開演約18分前から中央通路に姿を現し、自席の列へ横移動して着席する。終演45分後から退出を開始。
- `renderTownInterior`は時刻に応じて立位・着席のポーズを切り替える。プレイヤーと同じ座席に居る観客の描画は避ける。
- この段階は視覚的に再現する軽量な移動。観客による座席ブロック、衝突回避、個別チケット保有や退場時の移動経路探索は未実装。

### 5. WebGLと性能
- 3D扉は一度メッシュ生成し、描画ループでは角度変換だけを行う。
- `TownLife.hallStep`は現在の街の音楽施設レイアウトを一度計算しキャッシュ。重い街全体レイアウトをVR毎フレーム再生成しない。
- 室内の観客は`hallAudiencePose`の軽量補間だけで更新し、遠方の会場NPCは別のAIとして起動しない。
- 全体のWebGL/Quest描画負荷・実機動作は未確認。

- 動的な椅子の占有予約、観客間・プレイヤー間の衝突回避
- サーバー権限によるマルチプレイ入場券認証
- 他惑星・ユーザー制作の劇場への汎用入口ポータル
