# Universal Engine — NPC楽団・宿場の室内演奏・演奏ポーズ v0.9ao

## ベースと目的
このPRは音楽文化PR #64（`feature/music-culture-npc-20261101`）に積み上げる追加段階。先行する #60（作曲）→ #61（3D/VR演奏）→ #62（クラフト・楽器Asset）→ #64（街の演奏・教育・経済）の統合後に取り込む。

## NPC楽団の雇用
- 音楽文化パネルに「🎼 楽団の結成・雇用契約」を追加。
- 既存の`settlementLayout(townId).residents`内に存在する住人だけを、楽団員として選択できる。
- 役割：ギター24G、鍵盤28G、ベース22G、ドラム26G。
- 契約期間は開始惑星日から**3惑星日**。通常の`TownLife.coins`から契約金を一度だけ差し引き、当該NPCの`npcEarnings`へ計上。
- 1都市で最大4人、役割と住人の重複雇用なし。期限切れ契約を含め、旧契約データはロード時に検証。
- 途中解約は可能。ただし前払い契約金は払い戻さない。
- 既存の公演時間、会場、プレイヤーが所持するクラフト楽器との連携を継続。
- 雇用した楽団の人数によって、公演1回の技能・評判獲得が増加。ただし出演料は**既存の会場予算からの支払い上限を維持**し、契約だけでゲーム内コインは増えない。
- NPCに舞台上で会話し、その街の`TownLife.friendship`に親交を加算（1日1回まで）。評判も少し上昇。

## ライブ演奏の視覚化
- `music-band-geometry.mjs`を追加。職種別6種類（歌唱・ギター・鍵盤・ベース・ドラム・観客）、4フレームのオリジナル低ポリゴン姿勢を生成。
- 歌唱用マイク、ギター弦・ネック、鍵盤、ドラム・スティックを簡易モデルに組み込み、腕・手位置と観客の拍手が公演中に変化する。
- 24種類のWebGLメッシュを初期化時に生成し、レンダーループでは既存メッシュの切替だけにする。指一本ずつのモーションや実際のボタンへの接触判定は含まない。
- 雇用中の楽団員は既存の歌手とともに、街の野外ステージに登場する。NPCモデルは保存された街の住人IDと対応させる。
- 建物の局所座標は既存地表の`s.origin`と`this.cx/cz`に合わせ、地形・鉄道・宇宙船の原点管理は変更しない。
- 毎フレーム再生成していた街のレイアウト参照は`MusicCulture.venue()`にキャッシュ（セーブには含めず、既存の地形変換へ影響しない）。

## 宿場での室内公演
- 既存`TownLife.enter`で入室し、自由に歩ける宿屋／集会所（lodge）の室内へ、舞台・NPC音楽演奏者・観客のメッシュを表示。
- 宿屋に入室している場合は、音楽文化パネルから室内で演奏家へ話しかけたり、楽団員を雇用したり、公演に参加できる。
- 他の建物で屋内に入った場合は演奏参加不可。劇場・音楽学校の独立した専用室内はこのPRには含まれない。
- 室内は既存の`renderTownInterior`および歩行・出入口ロジックを利用。新しい別建物の保存、瞬間移動、建造物の再配置は行わない。

## 保存と安全性
- 既存`ue/music-culture`セーブ形式 version 1の任意キー `bandContracts`と`artistTalked`を拡張。旧セーブにフィールドが無ければ空の契約として復元。
- `v0_9an`ゲームスロットと端末ローカル保存の既存経路を再利用。
- プレイヤーの所持金は既存`TownLife`の通貨を使用し、不足・二重雇用・不正NPCは取引開始前に却下。
- 保存は端末ローカル。マルチプレイ認証・サーバー雇用契約、第三者のNPCの無断契約防止は本段階では未実装。
- 初期NPCの居住位置・通常生活AI・治安・交通経路など既存システムのコアには変更を加えない。

## 操作と確認
1. 宿屋や広場で「🎭 音楽文化」を開き、公演会場の近くまで歩く。
2. 「💬 演奏家と話す」で親交を深める。
3. 「楽団の結成・雇用契約」を開き、既存の住人と担当楽器を選び「この住人を雇う」。
4. 3日間は公演に契約した楽団員が表示される。出演すると技能・評判の共演ボーナス。
5. 宿屋のドアから既存の室内に入れば、室内ステージがある時は室内でも音楽文化パネルを使える。

テスト：`node --test universal-engine/planet-explorer/music-band.test.mjs universal-engine/planet-explorer/music-culture.test.mjs`

## 段階的な制限
- ローポリゴンの4フレーム演奏姿勢。楽器の精密な指板押弦、手・弓の物理IK、観客の経路探索、NPC間のリアルタイム楽器譲渡は未実装。
- 演奏家の雇用は既存都市のローカルな3日間契約。マルチプレイ・契約書・税・労働法・給与の継続支払は追加仕様が必要。
- 宿場室内の舞台は既存室内に表示する追加メッシュ。観客は簡易的な表示で、演奏を鑑賞する座席や立ち位置の精密なNPC AIは後続。
- Quest 3/3S、iOS Safariの実機試験とWebGLパフォーマンス計測は未実施。
