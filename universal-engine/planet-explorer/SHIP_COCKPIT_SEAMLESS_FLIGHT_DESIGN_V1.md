# Universal Engine — 宇宙船コックピット操作と地表→宇宙シームレス航行 設計書 v1

- 作成日：2026-11-02
- 区分：**実装設計／未実装機能の要件定義**（本書の追加だけではゲームの挙動は変わらない）
- 主な対象：iPhone Safari（タッチ）、PC（マウス・キーボード）、将来のQuest VR/MR
- 参照：既存のmain、未マージの [PR #70](https://github.com/hublab055-crypto/kamoku-world-monitor/pull/70)
- 変更原則：既存の徒歩・船内歩行・乗り物・VR入力・セーブを壊さず、コックピットと物理座標系を段階的に導入する

## 1. 到達目標

ユーザーが惑星の地上で宇宙船に近づき、船尾のハッチを開けて乗船し、船内を歩いて操縦席に着席する。専用UIで操縦して離陸、大気圏内を自由に飛び、雲・山・地平線が徐々に小さくなる様子を窓越しに見ながら大気圏を抜ける。宇宙空間で目的天体に向かい、再突入・着陸後に座席を立ち、船尾から地表に降り立つ。

ここで「シームレス」の意味は**UI切替だけでなく、船体のワールド位置・速度・姿勢、乗員の相対位置、窓外の描画が連続していること**である。単純な航行ゲージの満了により視点・船体を目的地点へ飛ばす仕組みは、最終仕様にはしない。

### 完了条件（ユーザー視点）

1. 船外・船内・操縦席を、必要な場面でのみタッチ操作のUIに切替えながら、同じ宇宙船として扱える。
2. 地表に接地した船へ徒歩で近づき、ハッチ・ランプを経由して船内へ移動。着席／起立時にも船と乗員の座標が飛ばない。
3. スロットル・操縦桿を操作すると、実際の位置・速度・姿勢が変わり、窓の外に反映される。
4. **地表→空→大気圏外→軌道／宇宙→目的地の空→地表**が、操縦席を維持して連続的に遷移する。
5. 途中で保存・再読込しても、天体・姿勢・速度・座席・ハッチ・ギア・貨物・燃料・乗員が一致する。

### 初期実装で含めないもの

高精度のN体重力積分、現実の6DoF空力完全再現、巨大な惑星全域の詳細地形同時描画、他プレイヤーとの物理同期は後続。**初期段階でも高度／位置がタイマーのみに依存しない**ことは維持する。

### 現状のギャップ

- 既存の航行は `stageProgress` と経過時間によって「上昇完了→軌道」「突入完了→着陸」を切り替える。上昇高度と速度の持続的な物理状態は未完成。
- PR #70の `ShipJourney.throttle` は 0〜1、スティックは左寄り／推力はその右で、今回の左右中央配置と逆噴射には非対応。
- `SurfaceStarship.takeOff()` は駐機情報を空中機体の6DoF状態に変換せず、`bodyId` を空にする。地表→宇宙を通した唯一の位置所有者が必要。
- `travelToCelestial()` は目的天体到着時に保存データを組み替えて `init(next)` を呼ぶ。最終的には船／乗員／カメラを保持したまま、背景世界だけを交換する方式へ移す。

## 3. コックピット画面のレイアウト

着席が成立したら、徒歩用スティックを非表示にして `ship-cockpit` 操作プロファイルへ切り替える。着席解除時は `ship-interior` 徒歩プロファイルへ戻す。両モードの入力は混在させない。

~~~text
┌────────────────── コックピット窓外ビュー ──────────────────┐
│ 速度  高度  上昇率  残燃料  機体姿勢  ハッチ/脚   [⚙ 設定] │
│                                                          │
│               連続した外界（地形→空→宇宙）               │
│                                                          │
│  [スロットル]      [操縦桿：ジョイスティック]  [ハッチ][脚] │
│  正/0/逆噴射        左右・上昇/下降          [火器][投下] │
└──────────────────────────────────────────────────────────┘
~~~

### 3.1 左下：スロットルレバー

- UI型式：縦レバー。上端 **+100%**、中立 **0**、下端 **-100%**。
- レバーは**指を離しても現在値を保持**（操縦桿とは違い、中立へ自動復帰しない）。
- 正域：前進推進。負域：**減速／逆噴射**。中立に明確なクリック位置を設ける。
- 誤操作防止：正推力の高出力から負推力へ一瞬で反転させず、操作目標値を変化率制限付きで実推力に反映する。速度が前進中ならまず制動、低速域で後退推力とする。
- 数値ラベルは **推力指令 -100〜+100%** とし、実速度の増減（m/s）とは混同しない。
- 既存の `setThrottle(0..1)` はそのまま上書きしない。`throttleCommand`（-1..1）を新設し、従来セーブの0..1を移行する。速度変化は物理更新ループで反映。
- エンジン停止・燃料不足・着陸作業中の制限は物理側のガードとUI双方に表示。

### 3.2 中央下：操縦桿

- 操作X（左右）：**ヨー**／左右旋回。操作Y（上／下）：標準の「直感操縦」では**上昇指令／下降指令**。
- **押している間だけ入力**し、離したら中立へ戻る（位置・速度が即停止する意味ではない）。デッドゾーンは約12%、対角入力は正規化する。
- 大気圏内では機首ピッチや揚力・垂直スラスターへの入力に変換し、高度と垂直速度を連続更新する。
- 宇宙空間では「上昇／下降」が地上座標に対し意味を失うため、**飛行モードをHUDに明記**し、宇宙姿勢制御ではYをピッチ操作へ切替える。切替時は入力を一旦中立化し急旋回を防ぐ。
- 拡張「詳細姿勢制御」では左右をヨー／ロール切替、上下をピッチにできる。初期表示はユーザーの希望する直感操縦。
- VRでは左右コントローラーの入力との二重適用を禁止。Quest入力が有効なフレームではタッチの操縦桿を操縦入力に加算しない。

### 3.3 右下：4アクション（固定の初期割当）

| 位置 | 短押し | 長押し／詳細 |
|---|---|---|
| A | 🚪 ハッチ開閉 | 気密・乗降状態の表示 |
| B | 🛬 ランディングギア展開／格納 | 降着装置状態・警告 |
| C | 🎯 火器管制（発射） | 兵装・照準・射撃可否パネル |
| D | 📦 物資投下 | 投下貨物一覧・数量・地点・確認 |

- 短押し／長押しは `mobile-controls.mjs` の割当機構を再利用し、設定から入れ替え可能。ただし**安全制限は割当を変えても解除されない**。
- ハッチは操縦席からの**遠隔操作**として扱う。接地／気密圧が安全／無移動／乗員がランプ通路にいないときのみ開ける。現行 `ShipJourney.toggleHatch()` は近接手動操作専用のため、別の安全検査付き `requestRemoteHatch()` を設ける。
- ギアは飛行状態・降下高度・速度・着陸前の自動展開を検査。地上で収納しようとして船体が沈み込まない。
- 火器は安全装置、残弾／エネルギー、クールダウン、狙い、味方の遮蔽・接近を判定。許可された状態でのみ発射。先にPR #70の射撃／発射演出を維持し、命中・損傷は次段階。
- 投下はアイテム名／数量／回収可能地点を表示して確認後に実行。**操縦桿操作中の誤タップで貨物を消費しない**。貨物数を一度だけ減らし、投下イベント・回収可能カプセルを永続化。
- 操作できない場合は単に無反応にせず、押下時に拒否理由を明示。非表示と無効状態（disabled）を区別。

### 3.4 スマホ実装上の表示ルール

- 画面下部の3領域を `safe-area-inset-*` と横向き／縦向きに追従させる。スマホ横向きで初期配置を優先し、縦向きでは窓外視界を塞がない縮小・折畳を行う。
- タッチ領域の重複を避け、指の移動でWebページがスクロールしない（`touch-action:none` は操縦用の要素だけ）。
- メニュー **「☰ 操作 → 👁 表示設定」** からスロットル・操縦桿・4アクション・航行HUD・補助パネルの表示を個別制御できるよう `ui-visibility.mjs` と接続する。
- 「全部非表示」でも表示設定への復帰手段を必ず残す。非表示状態は**入力状態と独立**し、非表示になった操縦部の保持ポインター入力は解除する。
- VRは手のモデル／トリガー／グリップ、PCはキー操作を維持。画面タッチの物理入力と別の `PilotCommand` に正規化する。

## 4. モードと航行状態を分離した状態機械

**プレイヤー所在**（徒歩・船内・着席）と**宇宙船の運動相**（地上・飛行・軌道）は独立に保持する。二重に「今は船内か？」を所有する状態変数を増やさない。

~~~text
playerContext:
  surfaceWalk → ramp → interior → cockpit
  cockpit → interior → ramp → surfaceWalk （地上でのみ）
flightPhase:
  landed → preflight → ascent → atmosphere → exosphere → orbit
                      ↑                           ↓
                  atmosphericFlight         transit/approach
                      ↑                           ↓
               atmosphericDescent ← entry ← destinationOrbit
                      ↓
                  touchdown → landed
~~~

- `ShipJourney.status` は暫定的な「ユーザー向け航行相」として残し、実体の `FlightDynamics` 状態から導出する。旧APIの `status` を直ちに削除しない。
- `ShipInterior` の `seated` と `ShipJourney.seated` は更新タイミングを一元化し、いつでも一致する不変条件にする。
- `landed` でも着席・船内歩行は可能。航行中の歩行は将来のG耐性・拘束具を伴う拡張対象であり、MVPでは最低限の船内歩行の連続性を保証。
- `ascent`→`atmosphere`→`exosphere`→`orbit` は高度・密度・エネルギー・軌道条件から遷移。**固定8秒や一定の進捗率だけで切り替えない**。
- 宇宙から再突入しても、逆順に同じワールド座標を通る。再突入地点は航路と船体位置から定まる。
- 手動離着陸が困難な場合は**オートパイロット**が同じDynamicsの入力を操作し、位置テレポートで代替しない。

## 5. 座標・空間参照系（最重要）

既存の地表 `ExplorerController.x/z`、天体の緯度経度、`ShipInterior.x/z` を維持しながら、新しい宇宙船位置を **太陽系基準のdouble精度**で一元管理する。

| 参照系 | 主な単位 | 用途 |
|---|---|---|
| Stellar / Solar frame | m（内部はdouble） | 太陽系の天体中心・船の惑星間位置 |
| Body-centered inertial | m | 天体中心の位置・速度・公転／周回 |
| Body-fixed（ECEF相当） | m | 自転する惑星に固定された地点、緯度／経度／高度 |
| Local ENU tangent | m | 地上地形、建物、着陸脚、衝突 |
| Ship local | m | 船室・座席・ハッチ・貨物・乗員 |
| Camera floating-origin | m（GPU float） | 近景描画・精度維持。ゲーム状態へ逆書込みしない |

- `solar-system.mjs` の `orbitalPosition(id,days)` は現在 **AU単位**。利用境界で `AU_M` を掛けてmへ変換し、数値だけを混ぜない。
- 惑星中心・地表姿勢を組み合わせ、船の `worldPose`（position + quaternion + linear/angular velocity）を一つだけ保持する。
- 船内の人の世界位置は **T_stellar_body × T_body_ship × T_ship_person**。回転にも平行移動にも同じ変換を使い、座席で固定しても人の位置を別系統で更新しない。
- 地表の `lat/lon/elevation` はbody-fixedから導出し、離陸後も運航主体の `bodyId` を空にしない。重力優勢天体が変わったときに参照元を更新する。
- GPUへは `worldPose - renderOrigin` で近傍座標を渡す（floating origin）。原点再基準化は画面だけに適用し、船・貨物・NPC・保存位置を動かさない。
- 様々な地形LODのoriginを変える際も、船体・船内・窓外・物資を**同じフレームの変換スナップショット**から描く。
- 極地方・日付変更線・天体半径差・自転を考慮した変換単体テストを用意。

### 不変条件

1. `ship.worldPose` はシミュレーション更新で一度だけ確定。描画側・UI側から変更しない。
2. 接地中の船体フットプリントと船内ハッチ出口は同じ `worldPose` に基づく。
3. 画面の窓外カメラは座席に固定され、船の向きと位置だけで外の景色が変わる。ロード時に外界の方位が突然反転しない。
4. 天体切替によって船の恒星系絶対位置が変わらず、訪問先の地形資産のみを差し替える。

## 6. 更新ループと飛行ルール

**一方向のデータフロー**：タッチ／XR／キーボード → 入力正規化 → 権限・安全判定 → 物理更新 → 描画・HUD・セーブ。

- シミュレーションは固定ステップ（例：1/60s、経過時間の上限を設ける）で進める。画面リフレッシュレートが異なっても航跡を保つ。
- 主要量はm、m/s、m/s²、kg、rad、sで統一。保存する `heightAGL` は地形からの差、`heightMSL` は天体基準を明示。
- 推進：`acceleration = thrustN / massKg`。燃料消費で質量が変わり、加減速・逆噴射は速度ベクトルを変更。レバーを0にしても宇宙空間では慣性が残る。
- 重力：初期は最も影響の強い天体の中心重力（高度に応じて変化）で十分。天体の重力圏を跨ぐ際は力の寄与を滑らかに遷移し、急な速度ジャンプを出さない。
- 大気：天体別の圧力・密度関数で抗力と揚力／姿勢安定を簡易適用。希薄な天体と真空天体は別条件。
- 高度操作：アシストモード中の操縦桿Yは垂直速度の目標へ変換し、上昇／下降を制御する。実速度・高度の変化はスラスター・重力・大気によって制限される。
- 地上着陸：前方／脚接地点で地形をサンプリング。降着脚展開、着陸速度、傾斜、クリアランスを満たしたときだけ接地。安全でない場合は警告・着陸拒否・自動復行。
- 船外ドアは大気差圧、速度、乗員の足場を検査して解放。飛行中の誤操作や衝突中の二重実行を防ぐ。
- 兵装・投下は1つのアクションにつき1件のイベントIDを作る。成功したイベントだけ弾薬・エネルギー・貨物を減らす。

## 7. 継ぎ目のない描画と世界ストリーミング

1. 近距離：地表の高詳細地形、船体・影、木・建物・NPC・地表貨物を表示。
2. 中高度：地形タイルLODを下げる。海岸線・山脈・都市のシルエットと大気の層を連続的に表示。
3. 高高度：惑星球面＋地表テクスチャへ漸進移行。最後の地形が突然消えたり別の島に化けたりしないよう同じ地理情報を使う。
4. 宇宙：天体位置は `orbitalPosition` を時間同期して描画。距離・視野に応じて天体LODを切替。
5. 目的天体へ接近：遠景球面→周辺地形プレビュー→地形メッシュを**バックグラウンドで準備**して交換。船内・船の座標／速度・カメラは破棄しない。
6. 着地時：実際に通った着陸地点と `surface-starship.mjs` の駐機フットプリントを一致させる。
7. 低スペック端末では遠方LODと地形更新頻度を調整し、窓外視野を優先。切替失敗時には現在の外景を保ち航行を中断せず、エラー状態を表示する。

**注意**：既存の `ship-shared-scene.groundScenePhase()` は進捗率から景観高度を生成する仮実装。最終的に `ShipDynamics` の実高度／位置から描画するよう差し替える。単に演出をつないだだけではこの項の完了としない。

## 8. 保存・復元・旧セーブとの互換

- 既存の `captureGame()`／`v0_aa`（SolarSystem、voyage、ship）を入口として、**StarshipWorldState schemaVersion=3**を追加。保存領域の丸ごと変更はしない。
- `ShipJourney schemaVersion=2` はロード時に旧 `throttle(0..1)` → 新 `throttleCommand(0..1)`、旧heading → yaw、旧駐機緯度経度 → stellar positionを計算する。未定義の速度は0、接地状態なら姿勢は地形に沿って構築する。
- 旧セーブの `ShipInterior schemaVersion=1`・貨物／ミッション状態・惑星別建築記録を移行し、プレイヤーの装備・伴走NPC・金銭・所有権を消さない。
- 保存中に船外／船内／コックピットが重複して生成されないよう `vesselId` と現在の所属コンテキストを一元管理。
- 惑星到着時に `solarSystem.surfaces` と `freshCelestialSave()` を介して個別地表資産を読み替え、**乗船した船のスナップショットと時刻は持続**。交換が失敗した場合は以前の船の位置・燃料・貨物にロールバック。
- カメラの位置補間・操縦桿のタッチ状態・DOM参照・GPUメッシュは保存対象外。復帰時は操作入力を安全な中立へ戻す。スロットル指令は保存し、ロード直後は推進を一時無効にして再開操作を要求する仕様を選べる。
- UI配置／ボタン割当は既存の `mobile-controls` 設定にまとめる。ゲーム進行保存とUI設定は分離。

## 11. 自動テスト計画

### 数学・操作テスト

- スロットル: -1 / 0 / +1、推力指令のスムージング、正→逆の安全な遷移、レバーを離しても保持。
- 操縦桿: X=-1で左旋回、X=+1で右旋回、Y=-1で上昇、Y=+1で下降（画面座標の上下を含む）、デッドゾーン、同時入力、指を離して中立。
- 機体: 推力0の宇宙空間で慣性保持、逆噴射で速度減少、燃料不足の推力拒否、角速度上限。
- 座標: 地表↔ECEF↔恒星系↔船内の往復誤差、日付変更線、極、月・惑星の異なる半径、公転日付の差。
- 航行: 高度・密度・速度条件でフェーズ遷移。固定時間満了だけで瞬間移動しない。
- 安全: 飛行中のハッチ拒否、接地時の安全な遠隔ハッチ操作、ギア未展開で着陸拒否、飛行中の降機拒否、誤射・投下重複防止。

### 結合テスト（主要な1本のシナリオ）

~~~text
地上で徒歩→船尾のハッチ→乗船→ハッチ閉→船内を歩く→着席
→スロットル前進→上昇→大気圏内で旋回→高度増加→惑星球面
→軌道投入→目的天体設定→巡航→再突入→逆噴射→ギア展開
→接地→エンジン停止→起立→船内を歩く→ハッチ→地表に降りる
→保存→再読込→同じ着陸位置と乗員・資産が存在
~~~

この間、`vesselId` と乗員IDを不変、位置／姿勢／速度を連続、世界切替前後にカメラの方位が不連続にならないことを数値検証する。

## 12. リスクと回避策

- **PR #70が未統合**：mainへ突然その機能を追加すると存在しないimportで起動不可になる。UIの実装はPR #70の安定化後に開始。
- **2つの航行実装**：`SpaceVoyage` と `ShipJourney` を一度に置換しない。船内実体のある `ShipJourney` を新エンジンの標準経路とし、旧経路は明示的な互換アダプターへ。
- **仮想の瞬間移動**：経過ゲージと表示高度を物理座標と区別し、実座標がない状態を「シームレス完了」としない。
- **保存データ破損**：ロードマイグレーション＋アトミックな天体世界切替＋一つ前のセーブ復元。
- **iPhone描画負荷**：地表の詳細物体を宇宙まで保持しない。LOD、地形メッシュの再利用、必要な天体だけの読み込み。
- **VRとの衝突**：表示だけでなく入力の所有権をContext単位で管理し、二重操作を排除する。
- **既存CIの失敗**：2026-11-02時点で既存の失敗48件が残っているため、各PRは「追加機能が失敗件数を増やさない」ことと新規テストの完走を最低条件とする。ただし正式な統合判断は回帰原因・実機確認を含める。
