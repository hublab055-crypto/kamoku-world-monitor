# Universal Engine — 二階建て拘置所・監視生活チュートリアル実装仕様書

- 設計日：2026-10-26
- 版：1.0（設計仕様／未実装）
- 対象：Universal Engine / planet-explorer（WebGL2、通常操作、Meta Quest 3S VR）
- 関連資料：[拘置所チュートリアル構想](./CUSTODY_TUTORIAL_PROPOSAL.md)
- 互換性：既存セーブ、既存の法律・鉄道保安・ワールドコア・VR移動を維持
- スコープ：建築モデル、開閉扉、複数フロア移動、NPC巡回／集団行動、食事と作業の日課、3日間の選択式導入

## 0. 目的と現在の課題

既存の留置所は、`railway-geometry.mjs#railwayJailGeometry` の単一メッシュと、`custody-cell.mjs` の固定矩形移動で構成されている。現在の看守は `render.mjs#renderRailwayJail` 内で局所座標(-1.1, 0, 6.0) に描画される一方、背後に廊下・外壁・床が続かないため暗闇に見える。格子は静的ジオメトリであり、可動扉の状態もない。

これを「牢屋単体」から「二階建て、中央吹き抜け、二階回廊、一階食堂、作業場、中庭のある、暮らして動く拘置施設」に拡張する。**プレイヤーは監督なしで外に出られないが、看守が扉を開き、他の囚人と一緒に実際に廊下・階段・食堂を移動できる**ことをコア体験とする。

初回導入チュートリアルは任意選択。通常の逮捕による勾留と仕様・刑期を混同しない。今回の資料は実装設計であり、建築3D・NPC・時間割などの実装完了を意味しない。

## 1. 建物ジオメトリ・寸法（基準案）

建物全体：幅約24m × 奥行約20m、基準床高 1階 y=0、2階床 y=3.8m。外壁高 7.8m程度、屋根・天窓・採光用窓を備える。

| エリア | 参考寸法・配置 | 用途 |
| --- | --- | --- |
| 二階居房 | 3.0 × 3.8m × 高さ3.2m程度、外周側に8〜10室 | ベッド、棚、小机、便器／桶、鉄格子扉 |
| 二階回廊 | 幅2.0〜2.2m、中央吹き抜け周囲 | 巡回、囚人の集団移動、手すり越しの視線 |
| 中央吹き抜け | 約11 × 9m | 一階の食堂等が見える。転落防止の手すり（高さ1.1m） |
| 階段 | 幅1.5m、踊り場あり | 二階回廊から一階へ連続歩行 |
| 一階食堂 | 約12 × 9mを基準に調整 | テーブル、長椅子、配膳口、水桶、皿 |
| 監視詰所 | 回廊・階段・出入口を見渡せる位置 | 看守交代、鍵管理、巡回開始地点 |
| 一階作業場 | 積み木台、納品窓口、工具管理 | 積み木作業の達成判定 |
| 中庭 | 建物の出入口を通って到達できる屋外区画 | 伐採用樹木、石材作業、監視 |
| 玄関・正門 | 外部ワールドへ繋がる施錠扉 | 釈放時のみ退出可能 |

レイアウトは概念配置であり衝突とNPC経路試験を通して確定する。独房の数、食堂席数、階段幅は「プレイヤー＋複数NPC」の同時移動を優先。狭すぎてNPCが扉前で永久停止しないこと。

### 1.1 見た目と照明

- 看守の背後を黒一色で終わらせず、石造りの床・外壁・廊下・階段・向かいの牢房・監視窓まで描画する。
- 朝は高窓・天窓から斜めの日差し、夜は壁のランプと廊下照明。ベースの環境光を0にしない。
- 壁・床・格子・階段・手すり・扉を別メッシュ化し、同じワールドメートル座標系で描画する。
- WebGL2の既存軽量レンダラーに合わせたメッシュバッチ・簡易光源の採用。新規Three.js依存を前提にしない。
- 独房からは「看守・廊下・回廊・食堂の生活音」を感じられる。一階は二階の囚人の移動が見える。

## 2. 扉・鍵・衝突

各独房には幅0.9〜1.0m・高さ約2.1〜2.2mの鉄格子扉を設ける。

### 2.1 扉ステート

`locked_closed → unlocking → opening → open → closing → locked_closed`

- 扉は蝶番まわりに0〜85度程度回転、開閉アニメーション約0.8〜1.2秒。
- 施錠中はプレイヤー・NPCともコライダーで通行不能。開いていても、扉パネルの占有空間は衝突判定する。
- 開扉は看守の認可によって実行。時間割は看守に行動命令を出すだけで、瞬時に通行可能へ切り替えない。
- 看守が扉へ到達し、解錠、開扉アニメーション完了、通路安全確認、その後に誘導。
- 正門と中庭門にも鍵と権限を設け、外部脱出を防止。釈放時は解除。
- クラッシュ・ロード直後は扉状態を正規化し、扉とプレイヤーが重なっていた場合は安全な歩行可能点へ復帰。開放途中など不安定な状態を保存しても復帰可能にする。

### 2.2 道筋と権限

- 地形・通常移動と独立した施設ローカル座標(x,y,z)を用いる。
- 実際に歩ける範囲を施設の複数階用ナビゲーションデータで表す（各階ポリゴン／ウェイポイント、階段リンク、扉を動的障害物として扱う）。
- 独房、二階回廊、階段、一階食堂、工房、中庭、受付、外部をゾーンIDで管理。
- 状態に応じて `permittedZones` を付与。独房から許可された活動地点への移動のみ可能。境界を超えようとすると看守が声を掛け、すぐに不可視壁で戻すのではなく、物理扉・柵で制限する。
- VRのHMD基準の高さとアバター移動を区別し、階段で酔いにくい緩やかな視点高さ補間（階段横の急なカメラ飛びを禁止）。
- 独房の既存矩形当たり判定はレガシー用アダプターとして残し、新施設では利用しない。

## 3. 囚人と看守のNPC

- 初期例：囚人6人（プレイヤー以外）、看守3人。実装時の負荷測定で増減可能。
- 囚人タイプ：無口、気さく、古株、心配性など軽い個性を持つ。過度な説明会話ではなく日常の一言で世界観を伝える。
- 看守ロール：巡回、居房解錠、隊列先導、食堂監視、作業監督、巡回引継ぎ、夜間施錠。
- 他の囚人にも独立した部屋番号・食堂席・作業担当・立ち位置がある。看守が開扉→囚人が出る→回廊で合流→階段を下りる→食堂に着席、を順番に実行する。
- 移動はAIの実空間移動（速度・旋回・歩行アニメ・簡易経路探索）。画面内でのテレポート移動や瞬間出現を禁止。
- 扉前・階段・配膳口には待機ポイントと通行優先順位を設定し、NPC同士を貫通させたり永久に詰まらせたりしない。
- 監視行動：許可エリア逸脱の警告、違反時の制止、作業終業時の声掛け。チュートリアルでは警告による即拘束・ゲームオーバーを起こさない。
- 看守との会話は最寄りの可視NPC＋距離判定＋許可された会話メニューを用いる。従来の看守に固定座標を前提としたVR会話は旧施設互換処理として維持。

## 4. 一日の時間割と施設イベント

時間は「拘置所内の施設時計」を独立して管理。既存の惑星シミュレーション `simWorld.clock` が逮捕中に停止しても、チュートリアル／施設内イベントが進む。夜間スキップ時にのみ惑星時刻との差分を反映する設計を検討する（既存刑期を二重に加算しない）。

| 時刻 | 場所 | 看守／囚人イベント | プレイヤーが覚える操作 |
| --- | --- | --- | --- |
| 06:30 | 二階独房 | 朝の起床、看守が点呼 | 起きる、見る、話しかける |
| 07:00 | 二階回廊 | 牢の鍵を順番に開け、隊列を形成 | ドア、NPC追従、階段 |
| 07:30 | 一階食堂 | 配膳・着席・朝食 | 持つ、食べる、飲む |
| 08:30 | 作業場／中庭 | 作業指示、工具の貸出 | 道具選択、採集 |
| 12:00 | 食堂 | 昼食と休憩 | 空腹と体力の関係 |
| 13:00 | 作業場／中庭 | 午後作業、数量確認 | 納品、持ち運び |
| 17:30 | 食堂 | 夕食 | 食事、囚人会話 |
| 18:30 | 二階回廊→独房 | 看守が各房へ誘導、点呼、施錠 | 自分の房を探す |
| 20:30 | 独房 | 消灯・就寝、翌朝へ | ベッド使用、回復 |

時刻はゲーム内時刻の例。プレイヤーが遅れた場合には呼び出しと再誘導を行う。NPCは指示待ちでも固まらず、割当タスクまたは待機行動を継続する。進行上重要なイベントは「定時＋前提成立」で起動させ、指定時刻を過ぎたら永久に失敗する仕組みにはしない。

## 5. 三日間の導入編（任意選択）

### 5.1 スタート

- 「はじめから」→「拘置所から始める（基本操作）」か「自由に開始」を選択。
- 初日はベッドで目覚める。看守「目が覚めたか。お前は誰だ？名前を聞こう」「お前は線路に侵入した罪で拘束されている」。
- 名前入力は通常UI、VRは入力可能な3Dパネルまたは仮名で開始し後から編集。日本語・英数字対応。
- 罪状は物語導入用。既存の罪状／罰金／手配度と連動させず、プレイヤー自身が選んだ本編スタートへ自然につなぐ。

### 5.2 作業

作業数の解釈：3日間ですべての作業を体験できる推奨コースを用意。一日の必須作業は一種として冗長な繰り返しを避ける。任意の追加作業は可能。

- 1日目：作業プレートへの積み木10個積載・納品（掴む、回す、置く）。
- 2日目：中庭の木5本伐採・所定場所へ納品（斧、伐倒、重量）。
- 3日目：石の採掘・破砕・納品（ツルハシ、重量と収納）。標準ノルマは「石材10kg」を暫定パラメーターとし実装テストで調整。
- 上記3種類は日課として選択でき、選択された作業のノルマ（積み木10個／日、木5本／日、石材は設定量／日）を適用。
- 作業は実際のオブジェクトと命中・配置・所有権で判定する。単なるボタン連打で勝手に達成させない。
- 食事、睡眠、会話など体験していない必須行動は、自然なNPC案内で補う。
- 食堂へ移動しない・看守との会話ができない等の詰まり対策としてヘルプ／ヒント／進行スキップあり。

### 5.3 刑期満了と釈放

三日目の勤務完了→夕食／就寝または看守の最終報告→刑期満了。看守が鍵を使って扉を開け、正門まで同行。釈放はメニューによる瞬間ワープではなく、できる限り歩いて外へ出る演出。

釈放時支給：
- テント×1、ベッドロール×1
- 10G
- パン×3日分、水×3日分（インベントリで実アイテムとして保持）
- 斧×1、ツルハシ×1

「釈放引渡し記録」と「インベントリ変更」は同じ保存処理で確定させる。先にフラグだけ保存して支給に失敗する事故を防ぎ、同一`grantId`の再処理は重複支給しない。重量超過時は受取箱に自動的に格納する。

釈放後は通常の町・地形・経済・鉄道・探索へ移る。法律システムの既存「捕縛→罰金／服役による釈放」の刑期・罰金を勝手に3日に変更しない。

## 6. VR・通常操作の共通契約

- VR: 左スティック移動、右スティック方向転換、右トリガーで会話対象を選択／使用、グリップで手に持つ、実際の腕動作で作業。ゲームパッドや通常UIにも同等操作を提供。
- 既存Quest物理ボタン割当（勾留中の看守会話A=保釈／B=服役等）を破壊しない。導入編の「食事・ドア・作業」インタラクションは文脈依存の決定操作に紐付ける。
- 音声読み上げは補助。必ず両眼ステレオで読める3D字幕パネル、会話選択肢と注視ハイライトを表示し、ブラウザのHTML重畳に頼らない。
- 階段や吹き抜けでHMDの急加速、床抜け、ちらつき、視差不一致を起こさない。必要に応じスナップターン、速度調整、補助移動モード。
- 独房内はVRでも立位・座位に対応し、ユーザー自身の実空間移動で柵や階段の中へ侵入してしまった場合にはゲーム側の衝突・境界を復帰させる。
- 目標：Quest 3Sで描画とコントローラー追跡が継続し、実行可能なフレームレートを維持（目標数値は実機計測後に確定）。

## 7. システム設計案

### 7.1 分割モジュール（新規想定）

- `custody-facility-geometry.mjs`: 建物／二階回廊／階段／食堂／中庭のジオメトリ
- `custody-facility.mjs`: ゾーン、ローカル座標、扉、衝突、階段リンク、権限
- `custody-schedule.mjs`: 施設時刻、食事、作業、点呼、夜間施錠の状態機械
- `custody-npc.mjs`: 囚人と看守、席・ベッド、ウェイポイント、隊列、監視AI
- `custody-tutorial.mjs`: 3日間の導入、名前、作業記録、報酬トランザクション
- `custody-interactions.mjs`: ベッド・食器・工具・納品・扉・看守の同一操作API
- `custody-facility.test.mjs`: 扉／衝突／時間割／セーブの回帰テスト

### 7.2 中央の状態データ例

```js
facilityState = {
  schemaVersion: 1,
  facilityId: "rail-detention-01",
  version: "atrium-2f-v1",
  facilityMinute: 450,
  doors: { "cell-2f-01": { phase: "locked_closed", angle: 0, authorisedBy: null } },
  inmates: [{ id: "player", cellId: "cell-2f-01", zone: "cell-2f-01", floor: 2,
    position: { x: 0, y: 3.8, z: 0 }, task: "wake" }],
  guards: [{ id: "guard-shift-a", task: "patrol-gallery", routeIndex: 0 }],
  schedule: { phase: "breakfast", escortGroupId: null },
  tutorial: { enabled: false, day: 1, phase: "wake", playerName: null,
    quota: { blocks: 10, trees: 5, stoneKg: 10 },
    completed: { blocks: 0, trees: 0, stoneKg: 0 },
    chosenWork: null, releaseGrantId: null }
};
```

- 一階と二階の座標は同一ワールド空間。階ごとに別の固定矩形を持たせない。
- `facilityState` と`law.custody`/`railwaySecurity.jailed`を区別。状態所有者は施設、司法判断は法システムという責任分離を維持。
- 新規施設シーンへ移行するとき、旧形式の牢内ポジションは安全な居房内初期位置にマッピング。旧セーブが読み込めること。
- 既存`renderRailwayJail()`は互換レンダリングとして段階的に代替。コードを削除せず、切り替えフラグで元へ戻せる。
- マルチプレイ拡張に備え、扉の鍵、タイムテーブル、報酬、位置修正はシミュレーション側の決定的なイベントとして扱う。クライアントごとの画面描画と分離。

## 8. 実装順（既存機能保護）

1. **建築・照明の先行対応**：牢の縮小、看守の背後の廊下、建物の内部、二階回廊・吹き抜け・一階食堂。従来の釈放ボタンは残す。
2. **扉と階段移動**：扉の開閉アニメ、鍵・物理衝突、複数階の連続移動、ゾーン権限、セーブ復元。
3. **看守と囚人の時間割**：巡回、解錠、集団移動、食堂への誘導、配膳、戻り／施錠。
4. **生活と作業の実操作**：食事、飲水、睡眠、積み木・伐採・採石の納品と所有権管理。
5. **3日間導入モード**：開始選択、名前入力、クエスト進行、台詞、報酬付与と正門の解放。
6. **VR最適化と受け入れ検証**：3D字幕、手の使用、負荷試験、既存セーブと現行刑罰の回帰。

各段階で正常動作を確認し、GitHubの独立PRと復帰可能なコミットに分割する。核となるUniversal Engineコアや他システムを直接改変しない。

## 9. 受け入れ条件／回帰試験

- 看守の背後が真っ暗な無限空間ではなく、廊下・階段・他の居房が見える。
- プレイヤーの独房に鉄格子扉があり、施錠中は通り抜け不能、開扉後だけ外へ出られる。
- 看守が決められた時刻に扉へ歩き、解錠、開扉、囚人を誘導する。
- 他の囚人も扉から出て二階回廊と階段を経由して一階食堂へ向かう。床・手すり・階段・他NPCとの衝突が成立。
- 食堂のNPCは席に着き、食事を摂り、食後の作業／帰房へ移動する。
- プレイヤーがついていかない場合に看守の再案内が発生し、進行不能にならない。
- VRの左スティック移動、物理ボタン、視点、高さ、既存の看守への会話と保釈・服役が維持される。
- 3日間のチュートリアルを選ばなければ既存の通常開始と逮捕システムは変わらない。
- セーブ・ロード・VRセッションの中断・再開後も、扉の状態、NPCの現在地、日程、作業納品、報酬が整合する。
- 報酬を二重支給しない。釈放後に手配度や拘束状態が正しく解消されるが、別件の犯罪記録は維持する。
- 無人のダミー空間で正常でも、同時に複数囚人が歩くと詰まる・黒背景になる・描画が破綻する場合は未完了扱い。
