# MR Avatar Presence（Quest 3/3S・試験実装）

## 入口
Universal Engine → XR設定 → 「👥 MR・アバター召喚」。Quest BrowserのWebXR immersive-arで起動する。

## 対象・操作
- アバターV10の既存保存ロスターから、**副官／機関士／同行者／自分**を呼び出す。同じ人物の再召喚は再配置、異なる人物は最大4体まで。
- XRのlocal-floorを使い、トラッキング開始位置から正面約1.8mの床に立つ。床ヒットテストが得られたときは付近の床（0.30m以内、距離0.65〜4.5m）の位置を採用。非対応では正面に置く。
- 「右トリガー」またはパネルの「📍 召喚・再配置」で選択中の人物を配置する。パネルはWebXRのDOM Overlayを利用。
- 表示縮尺は40%、100%、160%。待機、追従（最大0.8m/s・ユーザーから最低約1.55m間隔）、敬礼、グッドサイン、着席演出、立つ、削除。
- 召喚位置・追従状態はXRセッション限り。Universal Engineの惑星座標やセーブを変更しない。
- QuestのパススルーとV10 GLBのスキン付き描画。GLB読込前・一部モデル不可時のみ簡易人型を描画する。

## 既存機能との整合
- 2台QuestのMR対面（WebRTC）は既存の別モードのまま。
- VR身体操作、宇宙船操縦、MR惑星模型・卓上RTSへ介入しない。
- オリジナルの副官アバターのV10モデルと編集内容はrenderer.avatarV10から取得。
- 現実位置の情報はローカルなXRセッション処理だけに使う。ネットワークに送信しない。

## 確認・制限
- 対応WebXR環境のみ有効。Quest 3S実機のステレオ描画・床認識・複数体FPSは未検証。
- V10のスキニングシェーダーは実物のDepth Sensing遮蔽にまだ対応していない。アバターの前を実物が横切る場合も正しく前後しないことがある。
- 物理衝突・障害物回避・家具との接地・触覚反応はない。ハグ・握手の手追跡と物理グリップは次段階。
- MRで体験する人の安全に配慮し、人物は実体のない表示であり現実世界の視界や足元をふさぐ場合がある。

## 開発向け
- 実装: `mr-avatar-presence.mjs`, `xr-ui.mjs`, `render.mjs`, `index.html`
- ロジック回帰: `node --test mr-avatar-presence.test.mjs`
- セッション進入後、gl framebufferを用いるrenderは`XRSession.requestAnimationFrame`内のみ。
