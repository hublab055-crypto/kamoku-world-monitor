# MR Avatar Presence v0.11（Quest 3/3S・試験実装）

## 入口
Universal Engine → XR設定 → 「👥 MR・アバター召喚」。Quest BrowserのWebXR `immersive-ar`で起動します。

## 最大8人のMRアバター
- 既存V10: 副官／機関士／同行者／自分の4人。招待枠1〜4はこの4種類の外見を再利用する独立表示スロットです（8人の異なる専用GLBではありません）。
- 視線位置/右トリガーで床へ配置。40%/100%/160%の縮尺、待機、ついてくる、室内を散歩、座る、立つ、敬礼、グッドサイン、両手サイン、手を振る、お辞儀。
- 家具に座る操作は**登録済みの椅子・ソファ**に向かい、到着すると着席モーションへ移るものです。実物の座面と服や身体の遮蔽・物理接触は保証しません。

## 部屋・家具の登録
- 部屋の中心で「📍 部屋の基準点を登録」、部屋の幅/奥行（2〜15m）を設定。
- `"plane-detection"`を任意で要求し、WebXR `XRFrame.detectedPlanes`から平面の姿勢/ポリゴンを読んで壁・机等の候補を取り込みます。メタデータが椅子/ソファと明示する場合のみそのタイプを使用。カメラ画素・動画は読みません。
- 自動スキャンで誤認する場合は「椅子/ソファ/机/壁/障害物を登録」で視線ヒットの位置（未対応なら正面約1.8m）に寸法指定で登録。最後の家具登録は取り消せます。
- 散歩・追従では部屋境界と登録家具の矩形を使い、単純な衝突回避を行います。これは完全なナビメッシュや実物障害物検知ではありません。
- 室内データはブラウザ`localStorage`の`universal-engine:mr-room:20261122:v1`のみ。家具は部屋の**基準点からの相対座標**を保存します。

## 次回起動時の同一位置復元
- `"anchors"`を任意で要求し、`XRFrame.createAnchor` → `requestPersistentHandle()`で**部屋の中心のアンカー1つ**を保存。次回のMR開始時に`XRSession.restorePersistentAnchor(handle)`を呼び、毎フレーム`XRFrame.getPose(anchor.anchorSpace,referenceSpace)`で部屋の原点を更新します。
- 一度に8体を表示してもアンカーは部屋全体につき1つ。WebXRのアンカー容量を人物数に依存させません。
- 復元が許可されない、ブラウザ/環境が非対応、プライベートモード、部屋が変わった場合は自動で旧座標を適用**しません**。「部屋の基準点を登録」で位置合わせが必要です。家具の配置データ自体は残ります。
- GPS/方位は屋内のセンチメートル単位位置合わせに適しません。実位置情報・カメラ画像・屋内地図をネットワークへ送信しません。

## MR↔VR 境界扉と招待
- 「🚪 MRの扉を設置」で3D扉を部屋に登録。VR側にもゲートを描画し、近づくと切替操作を案内します。
- 「🚪 この仲間を招く」で明示的に選んだ**NPC**を、同じページ内のMR・VRセッション間で引き継ぎます。VR側の扉の周辺に表示できます。
- Quest Browserの`immersive-ar`と`immersive-vr`は別WebXRセッションです。ユーザー操作によって現在のセッションを終了し、**もう一度ボタンを押して**次のセッションを開始します。ドア通過で自動的に没入モードは変更しません。
- **他の実プレイヤーをネットワーク経由で招待する機能ではありません。** 既存のMR対面/WebRTCとは分離し、他人の部屋への入室には個別の招待と承諾が必要です。

## 限界・QA
- Quest 3Sの実機で、アンカー作成/復元、壁面平面検出、左右眼視差、V10のアニメーション、フレームレート、UI操作を確認する必要があります。
- Quest BrowserのWebXRでは生のパススルーカメラ画素はWebアプリから通常利用できません。WebXR Depth APIも対応状況に差があり、現在のV10スキンシェーダーに実物の深度遮蔽は未接続です。
- 体の動き・障害物回避は簡易的です。画面のNPCを避けようとして実際に歩く危険を生まないよう、利用者自身は現実の家具・Guardian境界に従ってください。
